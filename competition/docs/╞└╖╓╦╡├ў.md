## 一、先读懂 5 个关键参数

三个赛题的评分都围绕下面 5 个参数。先讲清楚它们的含义和影响，后面每道赛题都会用到。

| 参数 | 含义 | 影响哪个评分项 |
|---|---|---|
| **盯防阈值 dwell_target_s = 20 秒** | 对准同一个真目标累计盯满多少秒，才算"摧毁"。盯一会停一会没关系，只要累计到 20 秒就摧毁，且永久锁定。 | 击毁（赛题二、三） |
| **协同阈值 K** | 需要几架无人机**同时**盯这个目标。**赛题二 K=2**（必须 2 架同时盯）；**赛题三 K=3**（必须 3 架同时盯）。 | 击毁（赛题二、三） |
| **中断容忍 grace_s = 2 秒** | 盯防过程中目标短暂丢失的容忍时间。丢 ≤ 2 秒不算断，找回来会自动补上这段；丢 > 2 秒就清零，要重新累计 20 秒。 | 击毁（赛题二、三） |
| **精度容差 D_max** | 你上报目标位置的允许误差。赛题一 = **30 米**，赛题二 = **120 米**，赛题三 = **150 米**。偏 0 米满分，偏到 D_max 就是 0 分，中间线性扣。**D_max 越大越宽容**——赛题三目标更多更分散，所以放宽到 150 米。 | 目指精度（三题都有，含义不同，见各题与[§六](#六目指精度的两种口径)） |
| **用时基准 T0** | 全歼（把所有真目标打掉）多快算满分。赛题二 T0 = **240 秒**，赛题三 T0 = **360 秒**。≤ T0 满分；T0 到 T0+180 秒线性掉到 0；没全歼 = 0。**T0 越长说明任务越重**——赛题三有 10 个目标且需 3 架协同，所以给到 360 秒。 | 用时（赛题二、三） |

## 二、赛题一 · 单机搜索跟踪（1 架 UAV · 1 真目标 · 无诱饵）

**只有一个评分项：持续目指精度。**

### ① 持续目指精度（权重 100%，满分 100）

- **考什么**：你能否全程、准确地把小车的位置报出来——既反映**感知结果**（你看没看到、估没估准），又反映**决策跟踪效果**（你跟没跟住、稳不稳）。
- **怎么算**：你必须**每一秒**用 `report_target(纬度, 经度)` 上报一次小车位置。裁判按 **1Hz** 采样，算你上报的点离小车真值偏了多少米（记为 D）。
  - 每拍精度分 `p = clamp(1 − D / 30, 0, 1)`——偏 0 米满分、偏 ≥ **30 米**（D_max）0 分、中间线性。
  - **漏报的那一拍算 0 分**（不报 = 不会蒙到分）。
  - 每 **20 秒**一个窗口，**去掉这个窗口里最差的 2 拍**（类似比赛"去掉两个最低分"）作为容错。
  - 最终得分 = `（所有窗口里保留的拍的 p 平均值）× 100`。
- **跟感知的关系**：小车真值你看不到，位置只能靠相机检测 + 云台跟踪 + 多帧运动估计。你必须自己 `point_gimbal` 转云台找到它、跟住它、估准它的坐标，再每秒上报。报偏或漏报都会拉低分数。
- **容错**：每 20 秒白送 2 个"豁免名额"——短暂遮挡、抖动、最差两拍会被自动剔除，不扣分。
- **达标**：剔除最低分后平均精度 ≥ **60%**（即总分 ≥ 60）。
- **减分项**：无。

> 算分示例（duration = 20s，单个窗口）：
> - 全程精确上报（D=0）→ 20 拍 p=1，去 2 最低后 18 个 1 → **100 分**。
> - 前 10 秒精确、后 10 秒漏报 → 10 个 p=1 + 10 个 p=0，去 2 最低后剩 8 个 0 + 10 个 1 → 均值 10/18 ≈ **55.6 分**（不达标）。
> - 18 拍精确 + 2 拍报偏 60m（p=0）→ 去掉这 2 个 0，剩 18 个 1 → 仍 **100 分**（容错生效）。

## 三、赛题二 · 多机协同识别（3 架 UAV · 3 真目标 + 15 静止诱饵 · 无威胁）

**3 个评分项 + 2 个减分项。**

### ① 击毁（权重 50%）

- **考什么**：你打掉了几个真目标。
- **怎么算**：**2 架无人机（K=2）同时**对准**同一个真目标**连续盯满 **20 秒**（dwell_target_s），这个目标算"摧毁"。得分 = `打掉数 ÷ 3 × 100`。
- **跟感知的关系**：场上 18 个东西，只有 3 个是真目标，15 个是静止诱饵。**盯诱饵 20 秒什么都不会发生**。而且诱饵在代码层会伪装成真目标（`target_type` 字段撒谎），你认不出来——必须靠**多帧位置比对**：位置一直不动的 = 诱饵，在动的 = 真目标（详见 [§八](#八诱饵-vs-真目标怎么区分)）。盯错对象 = 白盯。
- **中断容忍**：盯防过程中目标短暂丢失 ≤ 2 秒（grace_s）不算断，自动补回；丢超过 2 秒清零重来。

### ② 目指精度（权重 30%）

- **考什么**：你上报的真目标位置有多准。
- **怎么算**：用专用接口 `report_target(纬度, 经度)` 上报。每个真目标**单独累计**你上报的点离真值的均方根误差（RMSE）：偏 0 米 = 满分；偏 ≥ **120 米**（D_max）= 0 分；中间线性。3 个目标的子分取平均 = 这项得分。
- **关键口径（与赛题一不同）**：每个目标在**整个运行期间**累计 RMSE（不是按固定窗口）。**目标一旦被摧毁，对该目标的新上报会被丢弃**——即它的 RMSE「冻结」在摧毁那一刻；但**摧毁之前已累计的样本仍然计入**它的子分，且**该目标本身仍留在分母里**（摧毁不会把它从平均里移除）。详见 [§六](#六目指精度的两种口径)。
- **跟感知的关系**：目标真值你看不到，位置只能靠相机检测 + 多帧运动估计。误差越小，分越高——逼你把目标跟准、估准。
- **防取巧（四条规则）**：① **从未上报过的目标算 0 分计入平均**（不能只盯一个目标躺平）；② **每秒每个目标最多记 1 次**（按裁判解析出的目标限速，与你上报时填的 `target_id` 标签无关——别想靠轮换标签高频刷点稀释误差）；③ **已摧毁的目标再上报直接丢弃**（别报"尸体"刷分）；④ 分母是**全部真目标数（含已摧毁）**——摧毁不会降低精度项的分母。

### ③ 用时（权重 20%）

- **考什么**：多快把 3 个真目标全部打掉。
- **怎么算**：全歼时刻 ≤ **240 秒**（T0）= 满分；240~420 秒线性掉到 0；没全歼 = 0。
- **影响**：你搜索、识别、盯防越快，这项越高。它把前两项的能力综合成"整体效率"。

### 减分项（只扣总分，不影响达标）

- **飞机过近**：两架无人机水平距离 < **200 米**，每次**进入**这个状态扣 **2 分**（持续接近只算 1 次，分开再接近再算 1 次）。
- **越界**：飞出地形边界（约 4.8×4.0 公里，即 `HeightSample.csv` 覆盖区，运行时由该 CSV 派生）超过 **500 米**，每次扣 **2 分**。
- **上限**：两项合计最多扣 **15 分**。
- 这两项只看飞机的真实位置，跟你相机看到什么无关——是飞行纪律要求。

### 达标

打掉 ≥ **2/3** 的真目标，**且** 总分 ≥ **70**（达标只看任务成就 `base_score`，不受减分项影响）。

## 四、赛题三 · 对抗集群搜索（10 架 UAV · 10 真目标 + 20 诱饵 · SAM 防空区 + 干扰区）

**4 个评分项 + 2 个减分项。**

### ① 击毁（权重 40%）

- **考什么**：打掉了几个真目标。
- **怎么算**：要 **3 架无人机同时**（K=3）对准同一个真目标连续盯满 **20 秒**（dwell_target_s）才算摧毁。得分 = `打掉数 ÷ 10 × 100`。
- **跟感知的关系**：30 个东西里只有 10 个是真目标，得先认出来（靠多帧位置判别诱饵，详见 [§八](#八诱饵-vs-真目标怎么区分)）。而且要凑齐 3 架同时盯——10 架最多同时处理 3 个目标，逼你做任务分配。
- **中断容忍**：同赛题二（≤2 秒回补，>2 秒清零）。

### ② 目指精度（权重 25%）

- **怎么算**：同赛题二（累计 RMSE、摧毁后冻结采集、分母含已摧毁目标，详见 [§六](#六目指精度的两种口径)），但 D_max 放宽到 **150 米**（目标更多更分散，容差相应放宽）。未上报目标算 0 分计入平均。

### ③ 用时（权重 25%）

- **怎么算**：全歼时刻 ≤ **360 秒**（T0）= 满分；到 540 秒掉到 0；没全歼 = 0。目标多（10 个）且需 3 架协同，所以比赛题二的 240 秒长。

### ④ 存活（权重 10%）　← 赛题三独有

- **考什么**：结束时还剩几架无人机。
- **怎么算**：`存活数 ÷ 10 × 100`。
- **跟感知的关系**：威胁你看不全——简报只给防空区的**近似外接矩形**（外扩约 20%，没有精确边界），动态干扰区位置完全未知，只能靠 `obs.self.jammed`（被干扰时自己感知到）+ 队友广播警告来推断。看不见威胁就飞进去，滞留 2 秒必死。规避约定：用 `fly_to(..., alt=3000)` 爬升到 SAM 顶（2500 m）之上。

### 减分项

同赛题二（过近 < 200 m、越界 > 500 m，每次各扣 2 分，合计上限 15 分）。

### 达标

打掉 ≥ **70%** 的目标，**且** 总分 ≥ **70**，**且** 存活率 ≥ **50%**（三条同时满足）。

> ⚠️ **赛题三总分会上下跳动**：随时间推进，打掉的目标在涨分、被打掉的无人机在掉分，两个方向相反。这是正常的——末帧（运行结束）落盘的成绩才是最终成绩。

## 六、目指精度的两种口径

赛题一的「持续目指精度」和赛题二/三的「目指精度」**虽然都叫精度、都靠 `report_target` 驱动，但计算口径完全不同**。这是最容易混淆的地方，务必分清。

### 6.1 赛题一：全程 1Hz 软命中 + 每 20 秒窗口去 2 最低

- **采样**：裁判按 1Hz 网格（每整数秒一个采样点）遍历整个运行时长 `[0, duration)`。
- **每拍得分** `p_t = clamp(1 − D_t / 30, 0, 1)`，其中 `D_t` 是你这一秒上报点离真值的距离。**漏报的秒** `D_t = 30` → `p_t = 0`。
- **窗口容错**：每 **20 秒**一个固定窗口，窗口内**去掉 2 个最低的 p_t**（不进分子也不进分母）。若某窗口样本数 ≤ 2，则整窗口豁免。
- **最终**：`100 × (所有窗口保留拍 p_t 之和) / (保留拍数)`。
- **含义**：考你**全程、持续、稳定**的跟踪能力——既不能漏报（漏报占豁免名额），也不能持续报偏。

### 6.2 赛题二 / 三：每目标全程累计 RMSE

- **按目标分桶**：每个真目标维护**整个运行期间**的累计误差平方和与上报次数（不是按 20 秒窗口）。
- **每目标子分**：`acc_t = 100 × max(0, 1 − RMSE_t / D_max)`，其中 `RMSE_t = √(该目标累计误差²和 / 上报次数)`。**从未上报**的目标 `acc_t = 0`。
- **摧毁后冻结采集**：目标一旦被摧毁，**对它的新上报会被丢弃**——它的 RMSE 就「冻结」在摧毁那一刻的累计值。但**摧毁前已累计的样本照样计入**它的子分。
- **分母含已摧毁**：最终精度分 = 所有真目标子分的平均，**分母 = 全部真目标数（含已摧毁的）**。也就是说，把一个目标打掉并不会把它从精度分母里移走——它冻结的子分仍参与平均。
- **含义**：考你**对每个目标的定位精度**。策略上：(a) 每个目标都要报（未报算 0 拉低均值）；(b) 摧毁后立即切换去报别的目标（继续报已摧毁的会被丢弃，纯浪费）；(c) 不必担心"打掉目标反而拉低精度分"——它的冻结子分是基于摧毁前你报得准不准。

> **为什么两种口径？** 赛题一只有 1 个目标、不打击，自然要考"全程持续跟踪的稳定性"，所以用时间序列 + 窗口容错。赛题二/三有多个目标、且要打击，重点变成"对每个目标定位准不准"，所以用每目标独立的累计 RMSE，并设计"摧毁冻结 + 分母含已摧毁"来防止"打掉一个就躺平"。

## 七、目指上报：专用接口 `report_target`

目指精度**只能**通过平台提供的专用接口上报，**不能用** `broadcast`/`send_to` 通信消息替代——通信消息是给队友看的，裁判不收。

### 7.1 接口

```python
from competition.sdk.core.commands import report_target

# 返回一个 Command 对象，放进 decide() 的返回列表里即可
report_target(lat, lon, target_id=None)
```

- **`lat`, `lon`**：你判定真目标所在的经纬度（WGS84）。
- **`target_id`**（可选）：你给这个目标贴的标签，**仅作审计用途**——它**不参与限速、不参与评分**。你可以不填。

引擎本身**不处理**这条命令（verb 是 `agent.report`），它由 runner 路由给评分器，用来算目指精度。

### 7.2 三条硬规则（代码强制）

| 规则 | 行为 | 应对 |
|---|---|---|
| **限速：1 报告 / 目标 / 秒** | 同一真目标 1 秒内多次上报，只记第一次。限速键是**裁判解析出的目标 uid**（按上报点离哪个真目标最近判定），**不是**你填的 `target_id` | 别想靠轮换 `target_id` 绕过限速高频刷点稀释误差——没用 |
| **已摧毁目标：上报丢弃** | 赛题二/三里，对已摧毁目标的上报整条丢弃，不计入任何桶 | 目标打掉后立即切换去报别的，别报"尸体" |
| **报"尸体"：整条丢弃** | 若你的上报点离某个**已摧毁**目标比离任何存活目标都近，认定你在报尸体，整条丢弃（不污染存活目标的桶） | 上报时确保坐标跟的是活目标 |

### 7.3 三题用法差异

- **赛题一**：必须**每秒都报**（1Hz 持续）。漏报那一拍 p=0，会占 20 秒窗口里仅有的 2 个豁免名额——连续漏报会迅速耗尽名额并拉低均值。
- **赛题二/三**：每个真目标都要报、尽量报准。不必每秒报（限速本身就是 1 次/秒/目标），但要在跟踪期间持续上报以压低 RMSE。

## 八、诱饵 vs 真目标：怎么区分

赛题二（15 个诱饵）、赛题三（20 个诱饵）里，**诱饵是核心干扰**。区分诱饵与真目标是感知 + 决策层的头号难题。

### 8.1 代码层：诱饵会伪装，类型字段靠不住

- 代码里目标的 `target_type` 只有两种字符串值：`"ground_vehicle"`（真目标）和 `"decoy_vehicle"`（诱饵）。
- 但当相机被诱饵骗到时（引擎按一定概率触发 `misid_flag`），诱饵的 `target_type` 会被**伪装成 `"ground_vehicle"`** 透传给你。所以**你无法靠 `obs.self.detection.target_type` 字段识破诱饵**——它对诱饵和真目标报同样的值。

### 8.2 渲染层（仅 UE 增强版）：视觉上有差异，但代码读不到

在 UE 增强版的渲染画面里，真目标与诱饵在**外观上有视觉区别**（车型、涂装颜色不同，且颜色接近以增加辨识难度）——这是渲染层为增加真实感做的视觉设定。

> ⚠️ **关键**：这个视觉区别**只存在于渲染画面里，代码层完全读不到**。你的 Agent 拿到的 `obs.self.detection` 只有经纬度、置信度、类型字符串，**没有任何"车型/颜色"字段**。除非你用 `--mode eval` 接入自研视觉感知算法（YOLO，见 [§九](#九感知层与决策层没写感知算法会怎样)）去识别渲染图像，否则无法利用这个视觉差异。判别诱饵**只能靠下面的运动学方法**。

### 8.3 可靠方法：多帧运动学一致性（静止 vs 运动）

| 特征 | 真目标 | 诱饵 |
|---|---|---|
| 是否移动 | **移动**（有轨迹、有速度） | **静止**（speed=0，位置不变） |
| 多帧位置 | 持续变化 | 几乎不变 |

**判别方法**：把连续多拍的 `detection.target_lat / target_lon` 记下来，若位置在多帧间基本不变 → 大概率诱饵，应离开；若位置在移动 → 真目标，跟上并盯防。参考实现见 `competition/baselines/swarm_distributed.py`。

> 💡 诱饵误判**不会直接扣分**（误识别惩罚已移除），但盯诱饵 20 秒什么都不会发生，会**白白浪费时间、拖慢用时维度**。所以识别诱饵的价值在于"别浪费盯防资源"。

## 九、感知层与决策层：没写感知算法会怎样

这一节回答选手最常问的问题：**「如果我没有感知类的算法，会怎样？我该怎么选参数？」**

### 9.1 两层分工

你的 Agent 有两个可 override 的方法，对应两层：

| 层 | 方法 | 你做什么 | 不做会怎样 |
|---|---|---|---|
| **决策层** | `decide(obs, dt)` （必须实现） | 解析 `obs`、返回控制命令（飞行、云台、通信、上报） | 不实现无法参赛 |
| **感知层** | `sensor(obs, dt)` （可选） | 自研目标检测，返回 `List[Detection]` | 不实现/返回 `None` → 平台用**默认识别器**替你检测 |

**关键**：感知层是**可选**的。绝大多数选手不需要写感知算法——平台提供默认识别器，你只需在决策层用它的检测结果。

### 9.2 默认识别器：AccuracySimulator（训练态）

当你**不实现 `sensor()`**（或返回 `None`）时，平台用 `AccuracySimulator` 给你产生 `detection`。它不是真识别，而是**按概率从引擎几何真值采样 + 加噪声**：

- **检出概率 `accuracy`**（默认 **0.85**）：目标在相机视场内时，每拍按此概率伯努利决定检出与否。命中才给你位置，未命中 `detected=False`。
- **位置噪声 `noise_sigma_m`**（默认 **50 米**）：命中时，给真值位置叠加一个高斯噪声（σ 米）。也就是说你拿到的 `target_lat/lon` 比真值平均偏 σ 米左右。
- **置信度**：命中时给一个 `∈ [accuracy×0.8, accuracy]` 的随机的 confidence。
- **诱饵伪装**：真值源在传给 AccuracySimulator 前，引擎已把诱饵按概率翻成 `ground_vehicle`（见 [§八](#八诱饵-vs-真目标怎么区分)），所以默认识别器的输出也会"被骗"。

> **防真值泄漏钳制（硬约束）**：`accuracy` 上限 **0.9**、`noise_sigma_m` 下限 **30 米**。即便你在命令行传更大的 accuracy 或更小的 noise，也会被钳制——这是为了杜绝"accuracy=1.0 且 noise=0 导致检测位置退化等于真值"的作弊。

### 9.3 detection 的扰动因素全貌（默认识别器下）

你拿到的 `obs.self.detection` 受这些因素影响，理解它们才能写好决策：

| 扰动因素 | 来源 | 对你的影响 |
|---|---|---|
| **是否在视场内** | 你的云台朝向 + FOV | 没瞄准就 `detected=False`；必须 `point_gimbal` 把目标框进视场 |
| **检出概率 accuracy** | AccuracySimulator 伯努利采样 | 即便对准了，也有 (1−accuracy) 概率这一拍检不到（抖动/丢帧感） |
| **位置噪声 σ** | AccuracySimulator 高斯加噪 | 检测位置比真值偏 σ 米左右，需多帧平滑/滤波压低误差 |
| **诱饵伪装** | 引擎 misid_flag | 诱饵被报成 `ground_vehicle`，类型字段骗你；靠运动学判别 |
| **通信干扰**（赛题三） | 动态干扰区 | 被干扰时通信失效（不影响 detection 本身，但影响协同） |

**所以「没感知算法」的典型结果**：你能拿到带 ~50m 噪声、85% 概率检出、且会被诱饵骗的检测结果。这足以写决策算法（跟踪、搜索、多帧平滑估坐标），但精度上限受 noise_sigma 制约——你上报的目指精度天然有数十米量级的误差。想要更高精度，要么多帧滤波压噪声，要么上自研感知。

### 9.4 两种运行模式（`--mode`）

| 模式 | 默认识别器 | 何时用 | 命令行 |
|---|---|---|---|
| **train**（默认） | AccuracySimulator（概率采样 + 噪声） | 开发调试、快速迭代、无 GPU | `--mode train --accuracy 0.85 --noise-sigma 50` |
| **eval** | YoloDetector（真实 YOLOv8 推理 UE 渲染图） | 最终评测、想用真视觉感知 | `--mode eval --yolo-model <路径> --photo` |

- **eval 模式**下，默认识别器换成 YoloDetector——它真的去识别 UE 渲染的云台相机画面（这时 [§八.2](#82-渲染层仅-ue-增强版视觉上有差异但代码读不到) 的视觉差异才可能被你的 YOLO 模型利用）。但 YoloDetector 需要 UE 渲染的相片帧（`--photo` 开启 PhotoCache）。
- **渲染门控降级**：eval 模式下，若某架 UAV 没拿到相片帧（比如 UE 未渲染/降级），会**自动降级回 AccuracySimulator**（每架 UAV 只警告一次），保证不崩帧。

### 9.5 自研感知（可选，进阶）

如果你有自己的检测算法，override `sensor(obs, dt)`：

- 返回 `List[Detection]` → 平台**直接用你的结果**（不走默认识别器）。
- 返回 `SKIP_DETECTION` → 端到端模式，跳过检测（你自己在 `decide` 里全包）。
- 返回 `None` 或不 override → 走默认识别器（见上）。
- `sensor()` 抛异常 → 容错回退默认识别器（不崩帧）。

> 多数选手**不需要**这一层。先用 train 模式 + 默认识别器把决策算法跑通，再考虑是否上自研感知。

## 十、总分怎么合成、达标与排名怎么定

理解这一节，你就明白"为什么减分不影响达标、为什么赛题三分数会跳"。

### 10.1 总分公式

```
base_score  = clamp( Σ 权重_k × 维度分_k , 0, 100 )        ← 任务成就分
penalty     = min( 15, (过近次数 + 越界次数) × 2 )           ← 纪律扣分（仅赛题二/三）
total_score = clamp( base_score − penalty, 0, 100 )         ← 最终总分
```

- 每个维度独立计 0–100 分，按权重加权求和得到 `base_score`。
- 赛题二/三的减分项从 `base_score` 里**额外扣除**，不参与权重比例。
- 任何一步都做了 `[0, 100]` 钳位，分数永远是 0~100 之间的数。

### 10.2 达标（passed）只看 base_score，不看减分

**达标用任务成就分 `base_score` 判定，不受减分项影响。** 设计意图：纪律性扣分（过近/越界）不应把"任务完成好但飞得糙"的队伍判为不达标——扣分只影响排名，不影响达标。

### 10.3 排名用 total_score

最终排名按 `total_score`（= base − penalty）。所以减分虽然不挡你达标，但会拉低你的名次——飞得干净仍有价值。

### 10.4 赛题三总分非单调是正常的

赛题三有"存活"维度（权重 10%）。随时间推进：打掉的目标在涨分（kill ↑），但被击落的无人机在掉分（alive ↓），两者反向叠加，导致 `total_score` 可能忽高忽低。这是"实时评分反映当前质量"的必然结果，**末帧快照定最终排名**，符合"一局定胜负"惯例。

## 十一、成绩从哪里读：评分 JSON

运行结束后，评分结果落盘到 `output/<run>.evaluation.json`（末帧完整评估）。前端可视化界面左上角的圆形总分按钮展开后，看到的也是同一份数据。核心字段：

```jsonc
{
  "profile": "multi_uav_coop_decoy",   // 赛题名（三题分别为 uav_search_track_car / multi_uav_coop_decoy / adversarial_swarm_search）
  "K": 2,                              // 协同阈值（赛题二=2、赛题三=3）
  "total_score": 73.5,                 // 最终总分 0–100（= base − penalty）
  "base_score": 79.5,                  // 任务成就分（达标只看这个）
  "penalty": 6.0,                      // 减分项合计（仅赛题二/三）
  "dimension_scores": {                // 各维度子分 0–100
    "kill": 66.7,
    "accuracy": 80.0,
    "mission_time": 100.0
  },
  "kill_rate": 0.667,                  // 击毁率（打掉数 / 真目标数）
  "alive_rate": 1.0,                   // 存活率（仅赛题三）
  "completion_rate": null,             // 赛题一为 None（无 completion 概念）；赛题二/三同 kill_rate
  "n_targets": 3,                      // 真目标总数
  "n_destroyed": 2,                    // 已摧毁真目标数
  "mission_done_time_s": 220.0,        // 全歼时刻（未全歼则 null）
  "n_reports": 412,                    // 你上报的、被采纳的目标报告总数
  "passed": true,                      // 是否达标
  "penalty_breakdown": {               // 减分明细（赛题二/三）
    "proximity": { "count": 2, "unit": 2.0 },   // 过近违规 2 次 × 2 分
    "boundary":  { "count": 1, "unit": 2.0 },   // 越界违规 1 次 × 2 分
    "cap": 15.0
  },
  "per_target": {                      // 每个真目标的盯防状态
    "10001": {
      "destroyed": true,
      "destroyed_at_s": 95.3,
      "dwell_accumulated_s": 20.5,
      "resets": 1,                    // 盯防被打断重来的次数
      "coop_ticks": 1210
    }
  }
}
```

**怎么用这些字段自查**：
- `total_score` 低于预期 → 先看 `dimension_scores` 哪一项低，再看对应字段（kill 低看 `n_destroyed`/`kill_rate`，accuracy 低看 `n_reports` 是不是太少或有目标没上报，mission_time 低看 `mission_done_time_s` 是否为 null 即没全歼）。
- 觉得分数被冤枉扣了 → 看 `penalty_breakdown`，确认过近/越界的计数是否合理。
- 赛题三想确认存活情况 → 看 `alive_rate`。

## 十二、常见误区（避坑指南）

| 误区 | 真相 |
|---|---|
| "我盯住一个目标 20 秒就能摧毁" | 赛题二要 **2 架**同时盯、赛题三要 **3 架**同时盯（K）。单机盯再久也不摧毁。 |
| "目指精度三个赛题都是按 20 秒算" | **不是**。赛题一是全程 1Hz + 每 20s 窗口去 2 最低；赛题二/三是每目标**全程累计 RMSE**、摧毁后冻结。详见 [§六](#六目指精度的两种口径)。 |
| "打掉一个目标，它就不算进精度分母了" | 错。分母含已摧毁目标，它冻结的子分仍参与平均。 |
| "盯诱饵会扣分吧" | **不会**。诱饵误判惩罚已移除——盯诱饵只是白费时间（拖慢用时），不直接扣分。但仍要靠多帧位置判别避开它们。 |
| "我用 broadcast 把目标坐标发给队友，裁判也会收" | **不会**。目指上报**必须**用专用接口 `report_target`，通信消息裁判不收。 |
| "我打掉一个目标后继续上报它的位置能刷分" | 已摧毁目标的报告**整条丢弃**。打掉就应立刻切换去盯/报下一个。 |
| "我多报几次能稀释误差" | 每秒每个真目标只记 **1 次**，且按裁判解析的目标限速，与你填的 `target_id` 标签无关。轮换标签绕不过去。 |
| "我只盯一个目标，把它做到满分就行" | 未上报的目标 acc = 0 计入平均，会把你这项分拉低。**每个真目标都要报**。 |
| "我能靠 target_type 字段认出诱饵" | 不能。诱饵被伪装成 `ground_vehicle`。只能靠**多帧运动学**（静止=诱饵、运动=真目标）。详见 [§八](#八诱饵-vs-真目标怎么区分)。 |
| "我看到渲染图里车型/颜色不一样，能用" | 仅当 `--mode eval` 接入 YOLO 自研感知时可能用上；默认识别器下代码层读不到车型/颜色。 |
| "赛题一我少报几拍没事" | 漏报那拍 p=0。每 20 秒只有 2 个豁免名额，连续漏报很快耗尽并拉低均值。 |
| "我没有感知算法就跑不了" | 能跑。不实现 `sensor()` 时平台用默认识别器 AccuracySimulator（检出概率 0.85、噪声 50m）。详见 [§九](#九感知层与决策层没写感知算法会怎样)。 |
| "赛题三分数怎么一会儿高一会儿低" | 正常现象。kill 在涨、alive 在掉，两者反向。**末帧成绩才是最终成绩**。 |
| "减分会让我不达标" | 不会。达标只看 `base_score`。减分只影响排名。 |
| "我看到队友/目标真值了，直接用" | 违规。评分只读地面真值，但选手 `obs` 在数据层强制只投影本实体——读到全局视图即作弊。 |
