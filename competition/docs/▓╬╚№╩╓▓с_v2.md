## 一、平台概述

### 1.1 OpenSim 是什么

OpenSim 是一个基于 C++ 引擎 + Python SDK 的实时无人机/车辆协同仿真平台，专为**无人值守 ISR（情报、监视、侦察）竞赛**设计。你需要用 Python 编写一个自主智能体（Agent），控制一架或多架无人机在信息受限条件下完成「搜索 → 识别 → 盯防摧毁 → 目标位置上报」的完整作战闭环。

### 1.2 核心设计理念

- **战争迷雾**：你的 Agent 代码中**物理上看不到**队友位置、目标真值、诱饵类型、动态威胁区位置。你只能依赖机载相机感知 + 受限通信 + 多帧运动学估计。
- **你只需实现一个方法** `decide(obs, dt) -> list[Command]`，平台包办引擎启停、观测构造、命令分发、实时评分、结果落盘。
- **信息隔离是数据层强制**，不是"有但不让读"——禁止访问的字段在 Observation 中物理上不存在。

### 1.3 平台为你做什么

| 平台负责 | 你负责 |
|---------|------|
| 启停 C++ 仿真引擎、加载地形 | 编写 Agent 类，实现 `decide()` |
| 以 ~10Hz 调用你的 `decide()`，传入 `obs` | 解析 `obs`、做出决策 |
| 将命令强制绑定到你的实体并执行 | 返回命令列表 |
| 实时评分、写 `output/*.evaluation.json` | — |
| 提供 3D 可视化（Three.js 或 UE 渲染） | — |

## 二、快速开始

### 2.1 系统要求

- **操作系统**：Linux x86-64，glibc >= 2.39（Ubuntu 24.04+ 推荐）
- **Python**：3.10+，需 `redis`、`pyyaml` 包
- **Node.js / Redis**：发行包已内置，无需预装
- **GPU**：仅 UE 增强版需要（>= 8 GB VRAM、Vulkan）

### 2.2 一键启动

```bash
tar xzf opensim-1.1.0-linux-x64.tar.gz
cd opensim-1.1.0-linux-x64/

./setup.sh     # 首次运行：环境检测 + 自动安装依赖
./start.sh     # 启动 Redis + bridge + 前端（浏览器自动打开）
./stop.sh      # 用完停止
```

浏览器打开后，在右侧面板选择赛题，点击「开始仿真」即可运行内置示例算法。

### 2.3 运行你自己的算法

把你的 Agent 文件放在包根目录，命令行运行：

```bash
PYTHONPATH=. python -m competition run --scenario search_track \
    --agent my_agent:MyAgent --duration 600 --start-sim --visualize
```

`--agent` 参数格式为 `module:ClassName`，如 `my_agent:MyAgent`。

## 三、三道赛题

三道赛题是**难度递进的阶梯**：单机入门 → 多机协同进阶 → 对抗集群高阶。

### 3.1 赛题一 · 单机搜索跟踪（`search_track`）

**定位**：入门级，让参赛者熟悉 SDK 基本用法和控制循环。

| 项目 | 内容 |
|------|------|
| 受控 UAV | **1 架**（固定翼，带云台相机） |
| 真实目标 | 1 辆移动车（速度 8 m/s） |
| 诱饵 | 无 |
| 威胁 | 无 |
| 通信 | 无（单机） |
| 默认时长 | 600 秒 |
| 继承基类 | `SearchTrackAgent` |

**任务背景**：单架无人机被投送到任务区，需自动搜索并持续跟踪一辆地面移动小车。目标是**持续、准确地上报小车位置**。

**关键规则**：
- 平台在 `obs.briefing.target_initial_pos` 中**给出目标初始位置**（这是三题中唯一给目标位置的赛题，作为入门辅助）。
- 评分只看**目指精度**：你必须每秒用 `report_target(lat, lon)` 上报目标坐标，按上报点离真值的距离软命中打分（D_max=30m），漏报拍记 0 分，每 20s 窗口去掉 2 个最低分。
- 无打击能力（`dwell_target_s = 0`），无需摧毁目标。

**可用命令**：`fly_to`、`set_heading`、`set_speed`、`point_gimbal`、`set_gimbal_fov`、`report_target`

### 3.2 赛题二 · 多机协同识别（`coop_decoy`）

**定位**：协同进阶，引入多机通信、诱饵识别、盯防摧毁机制。

| 项目 | 内容 |
|------|------|
| 受控 UAV | **3 架**（每架独立 Agent 实例） |
| 真实目标 | 3 辆移动车（速度 5~12 m/s） |
| 诱饵 | **15 辆静止诱饵车** |
| 威胁 | 无 |
| 通信 | 广播 + 点对点（受限） |
| 默认时长 | 600 秒 |
| 继承基类 | `CoopAgent` |

**任务背景**：3 架无人机分散部署，面对 3 个真目标 + 15 个诱饵。诱饵进入相机视场时按约 50% 概率被误识别为真目标（`target_type` 仍报 `"ground_vehicle"`），诱导你的算法误跟踪。

**核心机制**：

1. **盯防摧毁**：>= 2 架 UAV 同时盯防同一真目标累计 20 秒即判定摧毁。短暂中断 <= 2 秒不清零且会回补；中断 > 2 秒清零重来。
2. **诱饵识别**：诱饵是静止的，真目标是移动的——必须靠**多帧运动学一致性**判别（`target_type` 字段靠不住）。诱饵被 >= 2 架 UAV 连续跟踪满 20 秒后被识别。
3. **目指上报**：用 `report_target(lat, lon)` 上报判定为真目标的位置，按每目标 RMSE 评分（D_max=120m）。

**通信约束**（引擎强制）：

| 约束 | 限制 |
|------|------|
| 通信距离 | ~1000 m（超距：点对点失败有反馈，广播静默丢弃） |
| 单消息字节 | <= 50 字节（超出抛 `PayloadTooLarge`） |
| 发送频率 | <= 4 Hz（滑窗节流） |
| 收件箱容量 | 32 条 |

**关键规则**：
- **不再给目标位置**（`target_initial_pos = None`），但给 `target_count = 3`。
- 通信是你与队友**唯一**的协同途径——你看不到队友的位姿。
- 无诱饵类型识别能力——必须靠运动学判别。

**可用命令**：全部 UAV/云台命令 + `broadcast` / `send_to` / `report_target`

### 3.3 赛题三 · 对抗集群搜索（`adversarial_swarm`）

**定位**：最高难度，引入威胁区、动态干扰、分布式拍卖、生存压力。

| 项目 | 内容 |
|------|------|
| 受控 UAV | **10 架** |
| 真实目标 | 10 辆移动车 |
| 诱饵 | **20 辆静止诱饵车** |
| 威胁 | **防空区（SAM）+ 静态通信干扰区 + 动态随机干扰区** |
| 通信 | 复用赛题二 |
| 默认时长 | 600 秒 |
| 继承基类 | `SwarmAgent` |

**任务背景**：10 架无人机群面对高对抗场景：

1. **防空区（SAM）**：无人机进入防空区并滞留 >= 2 秒**必然被击毁**（`hit_probability = 1.0`）。被击毁的无人机从战场永久消失。
2. **静态通信干扰区**：无人机落入即通信失效，离开自动恢复。
3. **动态随机干扰区**：随时间随机生成/消失，位置事先未知，最多同时存在 2 个，半径 400m，生命周期 25s。

**威胁感知模型**：

| 威胁 | 你如何知道它 |
|------|------------|
| SAM 防空区（静态） | `briefing.approximate_zones`（仅给近似外接矩形 bbox + 面积 + 高度带，外扩约 20%，**无精确多边形**） |
| 静态干扰区 | `briefing.approximate_zones` |
| 动态随机干扰区 | `obs.self.jammed` 翻为 `true` 时**自行估计位置**，再 `broadcast("J:lat,lon")` 警告队友 |

**避险方式**：SAM 区 `alt_max = 2500m`，用 `fly_to(..., alt=3000)` 爬升到 SAM 顶之上规避。

**关键规则**：
- 地图边界约 6.6 km × 4.4 km（lat 26.97–27.03，lon 124.97–125.03）。
- 给 `target_count = 10` 和 `approximate_zones`，但**不给动态威胁位置**。
- 盯防摧毁需 **3 架同时**（K=3），累计 20 秒。
- 你的 UAV 若被击毁（`obs.self.status == "destroyed"`），runner 自动停止调用 `decide()`。
- 没有 `attack` 命令——杀伤靠区域裁决（SAM）或盯防达成。

**可用命令**：全部 UAV/云台/通信/上报命令

### 3.4 三题对比总览

| 维度 | 赛题一 | 赛题二 | 赛题三 |
|------|--------|--------|--------|
| 难度 | 入门 | 进阶 | 高阶 |
| 受控 UAV | 1 | 3 | 10 |
| 真实目标 | 1 | 3 | 10 |
| 诱饵 | 0 | 15 | 20 |
| 通信 | 无 | 广播 + 点对点 | 复用赛题二 |
| 干扰区 | 无 | 无 | 静态 + 动态随机 |
| 防空区击毁 | 无 | 无 | 有（滞留 2s 必击落） |
| 目标初始位置 | 给 | 不给 | 不给 |
| 目标数量 | 隐含=1 | 给（3） | 给（10） |
| 威胁区信息 | 无 | 无 | 近似 bbox |
| 盯防摧毁需要 K | N/A | 2 架 | 3 架 |
| 评分维度数 | 1 | 3 | 4 |
| 达标线 | 60 分 | 70 分 | 70 分（含存活率 >=50%） |

## 四、评分体系

### 4.1 总体公式

```
base_score  = clamp( Σ ( weight_k × dimension_score_k ), 0, 100 )
total_score = clamp( base_score − penalty, 0, 100 )
```

每个维度独立计 0–100 分，按 profile 权重加权求和得 `base_score`。赛题二/三另有**后置减分项** `penalty`，从 `base_score` 中扣除。**减分只影响排名，不影响达标判定**——`passed` 按 `base_score` 判定。

### 4.2 赛题一评分（单维度）

| 维度 | 权重 | 说明 |
|------|------|------|
| `accuracy` | **1.0** | 1Hz 上报目标坐标，按 `p_t = clamp(1 − D_t/30, 0, 1)` 软命中打分。漏报拍 p_t=0。每 20s 窗口去掉 2 个最低分。D_max=30m。 |

- 达标线：总分 >= 60。
- 赛题一无打击能力，评分只看目指精度——你必须**每秒**用 `report_target(lat, lon)` 上报。

### 4.3 赛题二评分（3 维度）

| 维度 | 权重 | 说明 |
|------|------|------|
| `kill` | 0.50 | 击毁真目标占比（共 3 个） |
| `accuracy` | 0.30 | 每目标全程累计 RMSE。D_max=120m。未上报目标 acc_t=0；目标摧毁后冻结采集，但摧毁前样本仍计入，分母含全部真目标 |
| `mission_time` | 0.20 | 全歼所有真目标的耗时。<=240s 满分，至 420s 线性衰减到 0 |

- 参数：K=2（2 架同时盯防），dwell_target_s=20s，grace_s=2s。
- 诱饵误判惩罚已移除（误跟踪诱饵不再扣分）。
- 达标线：kill_rate >= 2/3 且 base_score >= 70。

### 4.4 赛题三评分（4 维度）

| 维度 | 权重 | 说明 |
|------|------|------|
| `kill` | 0.40 | 击毁真目标占比（共 10 个） |
| `accuracy` | 0.25 | 每目标全程累计 RMSE。D_max=150m。口径同赛题二 |
| `mission_time` | 0.25 | 全歼所有真目标的耗时。<=360s 满分，至 540s 线性衰减到 0 |
| `alive` | 0.10 | 期末存活 UAV / 10 |

- 参数：K=3（3 架同时盯防），dwell_target_s=20s。
- 总分非单调：完成度上升、存活率下降，两者反向。
- 达标线：kill_rate >= 0.7 且 base_score >= 70 且存活率 >= 50%。

### 4.5 减分项（仅赛题二、三）

| 减分项 | 触发条件 | 单次扣分 |
|--------|---------|---------|
| 飞机过近 | 两架 UAV 水平距离 < 200m | 2 分 |
| 越界 | UAV 飞出地形边界 > 500m | 2 分 |

- 总扣分上限 15 分。
- 边缘触发：持续违规只计 1 次，离开后再次进入才计第 2 次。
- 被摧毁的 UAV 不触发这两项。

### 4.6 评分输出

评分每控制周期（~10Hz）实时发布，运行结束时写 `output/<run>.evaluation.json`。末帧 JSON 核心字段：

```json
{
  "total_score": 73.5,
  "base_score": 75.5,
  "penalty": 2.0,
  "dimension_scores": {
    "kill": 66.7,
    "accuracy": 80.0,
    "mission_time": 85.0
  },
  "kill_rate": 0.667,
  "alive_rate": 1.0,
  "n_destroyed": 2,
  "n_targets": 3,
  "passed": true,
  "per_target": { ... }
}
```

## 五、SDK 接口参考

### 5.1 Agent 基类与生命周期

你需继承对应赛题的 Agent 基类，实现 `decide()` 方法：

```python
from competition.sdk.scenarios.search_track import SearchTrackAgent   # 赛题一
from competition.sdk.scenarios.coop_decoy import CoopAgent             # 赛题二
from competition.sdk.scenarios.adversarial_swarm import SwarmAgent     # 赛题三
```

Agent 基类定义（`competition.sdk.core.agent.Agent`）：

```python
class Agent(ABC):
    def __init__(self, my_uid: str): ...           # runner 传入本实体 unique_id
    def configure(self, config) -> None: ...       # 可选；注入静态任务参数
    def reset(self) -> None: ...                   # 可选；每局首次 decide 前调用
    def sensor(self, obs, dt) -> Optional[List[Detection]]: ...  # 可选；自研感知层
    @abstractmethod
    def decide(self, obs, dt: float) -> list[Command]: ...      # 必须实现；~10Hz 调用
```

| 生命周期方法 | 调用时机 | 你要做什么 |
|-------------|---------|----------|
| `__init__(my_uid)` | 启动一次 | 存下 `self.my_uid`，它就是你要控制的实体 |
| `configure(config)` | 运行前一次 | 可选；读取静态任务参数 |
| `reset()` | 每局首个 `decide()` 前 | 可选；清空内部状态 |
| `sensor(obs, dt)` | 每个 `decide()` 之前 | 可选；自研感知层（见 §6） |
| `decide(obs, dt)` | 每个决策周期（~10Hz） | **必须实现**；返回命令列表 |

**5 个不变量**（务必遵守）：

1. `decide()` 除 `self` 内部状态外是纯函数——不直接读写 Redis/文件/网络。
2. 返回的命令列表**按序发布**，顺序敏感。
3. 命令**只作用于 `self.my_uid`**——runner 发布时强制注入 `unique_id = my_uid`，你无法越权控制其他实体。
4. 返回空列表 `[]` 表示本周期不发命令。
5. 赛题三中你的 UAV 若被击毁（`obs.self.status == "destroyed"`），runner 自动停止调用 `decide()`。

### 5.2 观测模型（`obs`）

`decide(obs, dt)` 每次给你的 `obs` 是固定三字段结构：

```python
obs.self        # SelfView — 本机可物理感知的自身状态
obs.comm_inbox  # tuple[Message, ...] — 本周期收到的队友消息
obs.briefing    # MissionBriefing — 赛前已知静态信息（整局不变）
```

#### SelfView — 本机自身状态

| 字段 | 类型 | 含义 |
|------|------|------|
| `uid` | str | 本机 unique_id（= `agent.my_uid`） |
| `lat` / `lon` / `alt` | float | WGS84 位姿 |
| `heading_deg` | float | 航向（度） |
| `speed` | float | 速度（m/s） |
| `gimbal_pan` / `gimbal_tilt` | float | 云台方位/俯仰（度） |
| `gimbal_fov_deg` | float | 相机视场角（度） |
| `detection` | Detection | 相机检测结果（识别层产出） |
| `status` | str | `"active"` / `"destroyed"` |
| `jammed` | bool | **本机当前是否被通信干扰**（仅赛题三） |
| `comm_stats` | CommStats | 本机通信统计（sent/delivered/received/rejected_*） |
| `photo` | Optional[bytes] | 最新相机帧 PNG（默认 photo_mode=auto 自动注入；仅 UE 渲染模式） |

#### Detection — 本拍检测结果

| 字段 | 含义 |
|------|------|
| `detected` | bool；是否有目标在相机视场内 |
| `confidence` | [0,1]；越居中越高 |
| `target_lat` / `target_lon` | 检测到的位置（**可能是诱饵误识别，不是真值**） |
| `azimuth_error_deg` | 相对光轴的方位偏移（度） |
| `target_type` | `"ground_vehicle"` 或 `""` |

> **诱饵伪装**：相机被诱饵骗到时，`target_type` 仍报 `"ground_vehicle"`——你**无法靠类型字段识破诱饵**。诱饵是**静止**的、真目标是**移动**的，必须靠**多帧运动学一致性**判别。

#### Message — 队友通信

| 字段 | 含义 |
|------|------|
| `sender_uid` | 发送者 uid（**不给发送方位姿**） |
| `payload` | <=50 字节字符串，**格式参赛者自定义** |
| `recv_time` | 接收时刻（sim_time） |

#### MissionBriefing — 赛前静态简报

| 字段 | 含义 | 赛题一 | 赛题二 | 赛题三 |
|------|------|--------|--------|--------|
| `self_uid` | 本机 uid | ✓ | ✓ | ✓ |
| `fleet_size` | 编队受控实体总数 | 1 | 3 | 10 |
| `mission_area` | 任务区域边界 | ✓ | ✓ | ✓ |
| `target_initial_pos` | 目标初始 (lat, lon) | **给** | 不给 | 不给 |
| `target_count` | 目标数量 | 隐含=1 | 给（3） | 给（10） |
| `approximate_zones` | 近似威胁区（bbox+面积+类型+高度带，外扩~20%，**无精确多边形**） | 无 | 无 | 给 |
| `params` | 白名单参数（如 `coop_k`、动态干扰区统计） | ✓ | ✓ | ✓ |
| `score_view` | 每拍实时得分快照（首拍 None） | ✓ | ✓ | ✓ |

### 5.3 控制命令

所有命令构造器在 `competition.sdk.core.commands` 中，返回 `Command` 对象（不可直接构造 dict）。

#### UAV 导航

```python
fly_to(lat, lon, alt=None, speed=None, loiter_radius=200.0, turn_direction="right")
# 导航到目标点并盘旋。speed: 15–40 m/s（引擎钳位）

set_heading(heading_deg)   # 设置航向
set_speed(speed)           # 设置速度，15–40 m/s
```

#### 云台 / 相机

```python
point_gimbal(pan_deg, tilt_deg)
# 云台瞄准。pan: -180~180，tilt: -90~90（下为负）。pan=0, tilt=-45 是地面搜索默认

set_gimbal_fov(fov_deg)
# 设置相机视场角，5–120°。宽 FOV 覆盖大但 confidence 低；窄 FOV confidence 高但覆盖小
```

> 相机只在视场内检测目标——必须先用 `point_gimbal` 瞄准，才能搜索/跟踪。

#### 通信（仅赛题二、三）

```python
broadcast(payload: str)
# 广播消息给所有队友。<=50 字节，超限抛 PayloadTooLarge

send_to(peer_uid: str, payload: str)
# 点对点发送。<=50 字节
```

受引擎四级限制：字节（<=50）/ 速率（4Hz 滑窗）/ 距离（~1000m）/ 干扰区。

#### 目指上报（三题都用）

```python
report_target(lat, lon, target_id=None)
# 你「判定真目标在 (lat,lon)」的意图信号。引擎不处理；runner 路由给评分器算精度。
# 限速 1 报告/目标/秒。
# 对已摧毁目标的上报、以及报"尸体"（上报点离已摧毁目标更近）均整条丢弃。
```

> **目指上报只能用这个专用接口**，不能用 `broadcast`/`send_to` 替代——通信消息是给队友看的，评分器不收。

#### 不存在的命令

- **没有 `attack` / `fire` / `launch`**：杀伤靠引擎区域裁决（SAM）或盯防达成（20s）。
- **没有 `deploy_decoy`**：诱饵是场景静态实体。
- 赛题一不含通信命令，但含 `report_target`。

## 六、感知层与决策层架构

### 6.1 架构概览

```
┌─────────────────────────────────────────────────────┐
│                   Runner（平台）                      │
│                                                      │
│  WorldState ──→ isolation ──→ Observation             │
│       │                         │                    │
│       │                    ┌────▼──────────────┐     │
│       │                    │  agent.sensor()   │     │
│       │                    │  (可选，自研感知)  │     │
│       │                    └────┬──────────────┘     │
│       │                         │ 返回值             │
│       │                    ┌────▼──────────────┐     │
│       │                    │ DetectionResolver │     │
│       │                    │   三态编排分发     │     │
│       │                    └────┬──────────────┘     │
│       │                         │                    │
│  _extract_truth()               │                    │
│  (引擎几何真值)                  │                    │
│       │                         │                    │
│       └──────────→ AccuracySimulator                 │
│                    (内部通道，选手不可见)              │
│                                                      │
│                    ┌────▼──────────────┐             │
│                    │ agent.decide()    │             │
│                    │ (必须实现)        │             │
│                    └────┬──────────────┘             │
│                         │ list[Command]              │
│                         ▼                             │
│                    publish(uid, cmd)                  │
└─────────────────────────────────────────────────────┘
```

平台采用**感知层 + 决策层分离**的架构：

- **感知层**（可选）：负责产出 `Detection`。不实现时平台用默认识别器。
- **决策层**（必须）：`decide(obs, dt)` 解析 `obs`、返回控制命令。

### 6.2 感知层三种模式

感知层通过 `agent.sensor(obs, dt)` 的返回值决定使用哪种检测来源，由 `DetectionResolver` 统一编排：

| 返回值 | 含义 | 使用场景 |
|--------|------|---------|
| `None`（基类默认） | 未覆盖，走默认识别器 | **绝大多数选手** |
| `List[Detection]`（非空） | 自研识别结果 | 自研 YOLO 等感知模型 |
| `[]`（空列表） | 选手明确"本帧无检测" | 自研感知，本帧无目标 |
| `SKIP_DETECTION` | 端到端，跳过所有识别器 | 端到端 RL 选手 |

### 6.3 无感知层的接入方式（默认模式，推荐大多数选手）

**不需实现 `sensor()` 方法**。平台自动用 `AccuracySimulator` 作为默认识别器。

**AccuracySimulator（train 模式）**：不真识别，按概率从引擎几何真值采样 + 加噪：

- 检出概率 `accuracy`：默认 **0.85**（钳制上界 0.9）
- 位置噪声 `noise_sigma_m`：默认 **50 米**（钳制下界 30 米）
- 诱饵在传给识别器前已被引擎按概率伪装成 `ground_vehicle`，所以默认识别器也会被骗

**run 命令的默认行为**：

```bash
python -m competition run --scenario search_track --agent my_agent:MyAgent
# 默认 --mode train --accuracy 0.85 --noise-sigma 50
```

**这意味着**：你拿到的 Detection 有 ~15% 的漏检率、位置带 ~50m 高斯噪声、会被诱饵骗。要想获得更好的精度，可以用多帧滤波（如 EMA、卡尔曼滤波）压低噪声。

### 6.4 自研感知层

如果你有自研的目标检测模型（如 YOLOv8），可以覆盖 `sensor()` 方法：

```python
class MyAgent(SearchTrackAgent):
    def sensor(self, obs, dt):
        # 从 obs.self.photo 读取 UE 渲染的相机帧（PNG bytes，默认 auto 自动注入）
        if obs.self.photo is None:
            return None  # 无帧 → 回退默认识别器

        # 你的模型推理逻辑
        detections = self.my_yolo_model.detect(obs.self.photo)
        if not detections:
            return []  # 本帧无检测

        return [
            Detection(
                detected=True,
                confidence=0.92,
                target_lat=...,
                target_lon=...,
                target_type="ground_vehicle",
            )
        ]

    def decide(self, obs, dt):
        if obs.self.detection.detected:
            # 使用你自己的感知结果
            ...
```

**eval 模式**：平台也内置了 YOLOv8 识别器（`YoloDetector`），通过 `--mode eval --yolo-model <路径>` 启用。eval 模式下需 `--photo` 提供相片帧；无帧时自动降级回 `AccuracySimulator`。

### 6.5 端到端模式

如果你不需要 `Detection` 字段（如端到端 RL 直接从 `obs.self.photo` 图像像素决策），返回 `SKIP_DETECTION`：

```python
from competition.sdk.core.observation import SKIP_DETECTION

class MyAgent(SwarmAgent):
    def sensor(self, obs, dt):
        return SKIP_DETECTION  # 跳过所有识别器

    def decide(self, obs, dt):
        # obs.self.detection 将是空占位
        # 你直接从 obs.self.photo 做出决策
        ...
```

## 七、信息隔离机制

这是 SDK 与普通仿真器最大的区别，也是防作弊的核心机制。

### 7.1 隔离原理

构造每个 Agent 的 `Observation` 时**只读本实体**——其他实体的位姿/真值/检测结果**物理上不存在于 Observation 中**（不是"有但不让读"）。隔离在 `competition.sdk.core.isolation.build_obs()` 中强制执行：

- 只读取 `world_state.entities[entity_uid]`（本实体）
- 其他实体和动态 zone 从不访问
- 本机引擎几何真值**绝不放入** `obs.self.detection`（该字段初始为空占位，由识别层覆盖）

### 7.2 你拿不到的信息

| 信息 | 你能否拿到 | 如何间接获取 |
|------|----------|------------|
| 队友 UAV 的位置/姿态 | 不能 | 通过 `broadcast`/`send_to` 交换坐标 |
| 目标真值位置/轨迹 | 不能 | 靠 `detection.target_lat/lon` 多帧滤波估计 |
| 诱饵真值 | 不能 | 靠多帧运动学一致性判别（静止=诱饵） |
| 动态干扰区位置 | 不能 | 靠 `obs.self.jammed` 自感知 + 广播预警 |
| 其他实体的检测结果 | 不能 | 靠通信共享 |
| 队友的 `status` 字段 | 不能 | 靠通信心跳超时推断 |

### 7.3 合法信息源

| 信息源 | 说明 |
|--------|------|
| `obs.self` | 本机位姿、云台、检测结果、通信统计、干扰状态 |
| `obs.comm_inbox` | 队友发来的消息（仅 sender_uid + payload） |
| `obs.briefing` | 赛前静态信息（目标数量、近似威胁区、任务区域） |

## 八、参考实现

平台提供了三套内置示例算法（`competition/baselines/`），可作为你的算法对照基线。

### 8.1 赛题一参考：`search_track_fsm.py`

**类名**：`FsmAgent`，简写 `baselines.search_track_fsm:FsmAgent`

**策略**：三状态 FSM（ACQUIRE → SEARCH ↔ TRACK）

- **ACQUIRE**：读取 `briefing.target_initial_pos` 直飞目标初始位置
- **SEARCH**：阿基米德螺旋搜索 + 云台正弦俯仰扫描（FOV=70°）
- **TRACK**：EMA 位置滤波（alpha=0.15）+ 速度估计 + 静止检测 + 前向预测（feed-forward lead）驱动飞行 + LOS 几何瞄准云台

**关键技巧**：
- 用 `set_gimbal_fov(70)` 扩大视场角，降低目标移出视场的概率
- EMA 位置滤波器压低 50m 检测噪声到 ~12m，使云台跟踪稳定
- 用 `_los_angles()` 做精确几何 LOS 瞄准，而非比例控制

### 8.2 赛题二参考：`coop_distributed.py`

**类名**：`CoopDistributedAgent`，简写 `baselines.coop_distributed:CoopDistributedAgent`

**策略**：纯通信协同 + 诱饵运动学判别

- **SEARCH**：uid 哈希分 3 个扇区，各 UAV 独立搜索
- **VERIFY**：对检测到的候选目标做线性回归速度估计（~8 秒预算），速度 > 3 m/s 判定为真目标，< 2.5 m/s 判定为诱饵
- **TRACK**：近距离盘旋（loiter_radius=100m）+ heading 补偿云台瞄准 + 仅在速度 > 3 m/s 时上报

**关键技巧**：
- 用线性回归斜率测速比 EMA 漂移量更可靠（在 50m 噪声下 EMA 漂移有 ~90% 假阳性）
- 已知诱饵位置记录到 `_known_decoys` 列表，下次检测到附近位置跳过
- 通信：`broadcast("T:lat,lon")` 共享目标坐标

### 8.3 赛题三参考：`swarm_distributed.py`

**类名**：`SwarmDistributedAgent`，简写 `baselines.swarm_distributed:SwarmDistributedAgent`

**策略**：分布式协同 + 静态避险 + 动态干扰感知

- **SEARCH**：相位偏移螺旋（10 架 UAV 通过 uid hash 分配不同相位，扇出搜索）
- **静态避险**：飞行路径点落入 `approximate_zones` bbox 时，爬升到 `alt_max + 1.0`（保守规避）
- **动态干扰感知**：`obs.self.jammed` 触发时广播 `"J:lat,lon"` 警告队友
- **目标共享**：运动学确认后广播 `"T:lat,lon"`，收到后收敛协同跟踪
- **诱饵判别**：滑动窗口位移检测（20 帧内最大位移 > 阈值 → 真目标）

**关键技巧**：
- 用 `_in_any_approx_zone()` 检查 bbox 而非精确多边形（因为 briefing 只给 bbox）
- 用 `fly_to(..., alt=3000)` 爬升到 SAM 顶（2500m）之上规避
- 每 10 拍广播一次，控制通信频率

## 九、常见问题

**Q1：我看不到队友的位置，怎么协同？**

这正是赛题设计。协同只能通过 `broadcast()`/`send_to()` 交换信息（如自己发现的目标坐标、威胁警告），然后各自在本地维护一份"态势图"。

**Q2：怎么区分诱饵和真目标？**

诱饵静止、真目标移动。把连续多拍的 `detection.target_lat/lon` 记下来，位置不变的极可能是诱饵。`target_type` 字段靠不住（诱饵会伪装成 `"ground_vehicle"`）。参考 baseline 用线性回归或滑动窗口位移检测。

**Q3：怎么"摧毁"目标？没有开火命令？**

对同一真目标持续盯防（相机对准）累计 20 秒即判定摧毁，需满足协同阈值 K——赛题二需 2 架同时、赛题三需 3 架同时。策略重点是稳定跟踪 + 协同分配。

**Q4：我的 UAV 被击毁了怎么办？**

赛题三中，runner 检测到 `obs.self.status == "destroyed"` 后自动停止调用 `decide()`，你无需在代码里处理。但队友只能通过**通信心跳超时**察觉你失联。

**Q5：`--seed` 是干什么用的？**

随机化场景（目标轨迹、威胁区、起始位置都从 seed 派生）。同 seed → 同场景，完全可复现。用于泛化训练与回归测试。

**Q6：可视化界面显示的分数和最终 `evaluation.json` 一样吗？**

一样。两者来自同一个评分运行时，可视化只是把结果渲染成面板。

**Q7：不需要写感知层也能参赛吗？**

能。绝大多数选手不需要实现 `sensor()`。平台默认用 `AccuracySimulator` 提供带噪声的检测结果（~85% 检出率、~50m 噪声），你只需在 `decide()` 中做决策。想提高精度可以用多帧滤波压低噪声。

**Q8：通信 payload 的 50 字节限制怎么算？**

按 UTF-8 编码后的字节数计算。例如 `"T:27.00123,125.00456"` 是 22 字节。建议与队友约定紧凑格式：`T:` 目标、`J:` 干扰、`R:` 集合。

**Q9：`fly_to` 的 loiter_radius 设多少合适？**

赛题一跟踪时建议 200m（保持距离），赛题二/三盯防时建议 100m（靠近目标以确保稳定的检测信号）。radar 过小会导致 UAV 盘旋过紧，heading 变化剧烈，云台跟不上。

**Q10：赛题三 SAM 区怎么规避？**

SAM 区 `alt_max = 2500m`。约定用 `fly_to(..., alt=3000)` 爬升到 SAM 顶之上。平台没有专用规避命令——爬升就是你表达规避的方式。
