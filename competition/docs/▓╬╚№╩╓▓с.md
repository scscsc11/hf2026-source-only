## 一、平台定位

### 1.1 这是什么

**Simulation** 是一个 基于C++并实现Python封装的 实时无人机/车辆协同仿真平台，专为 **「无人值守 ISR（搜索—识别—打击）竞赛」** 而设。

在这场竞赛中，你需要用 Python 实现一个自主智能体（Agent），控制一架（或一群）投送到陌生任务区的无人机，在**信息受限**的前提下完成「搜索 → 识别 → 盯防打击 → 目标位置上报」的完整作战闭环。

> **ISR** = Intelligence / Surveillance / Reconnaissance（情报、监视、侦察）。本竞赛中的"打击"不是发射武器，而是**持续盯防同一真实目标 20 秒即判定摧毁**（见 [§4.2](#42-三大核心机制)）。

### 1.2 你要解决的核心难题

平台刻意制造了**「战争迷雾」**——你在 Agent 代码里**物理上看不到**这些信息：

- ❌ 队友无人机的位置、姿态、检测结果
- ❌ 真实目标的地面真值（ground truth）位置与轨迹
- ❌ 诱饵车与真实目标的类型区别（诱饵会伪装成真实目标）
- ❌ 动态通信干扰区的精确位置

你只能依赖：**机载相机感知** + **编队受限通信** + **多帧运动学估计**来还原战场态势。

### 1.3 平台为你做什么

你**只需实现一个方法 `decide(obs, dt)`**，平台包办其余一切：

| 平台负责 | 你负责 |
|---|---|
| 启停仿真引擎、加载地形（release 包已预编译，无需自行构建） | 编写 Agent 类、实现 `decide()` |
| 以 ~10Hz 调用你的 `decide()`，把 `obs` 交给你 | 解析 `obs`、做出决策 |
| 把命令**强制绑定到你的实体**并执行 | 返回命令列表 |
| 实时评分、写 `output/*.evaluation.json` | — |
| 提供 3D 可视化（标准版 Three.js 自渲染；UE 增强版可渲染真实仿真视频流并支持云台拍照保存至本地，均不影响评分） | — |

## 二、发行包与快速开始

参赛者会拿到**两个预编译发行包之一**（均为 `tar.gz`，解压即用，**无需编译**）：

- `Simulation-1.1.1-linux-x64.tar.gz` —— 标准版（Three.js 自渲染可视化）
- `Simulation+UE-1.1.1-linux-x64.tar.gz` —— UE 增强版（Unreal Engine 真实渲染）

> 两个包的仿真引擎、评分、SDK、赛题逻辑**完全一致**，区别仅在可视化渲染方式。

### 2.1 两个发行包：Simulation 与 Simulation+UE 的区别

> ℹ️ **以下 UE 相关内容仅适用于 UE 增强版。标准版参赛者可跳过 §2.1 末尾的对比表和 §5.7-5.8 的 UE 部分。**

| 维度 | `Simulation-1.1.1`（标准版） | `Simulation+UE-1.1.1`（UE 增强版） |
|---|---|---|
| **压缩包大小** | ~300 MB（解压后约 1.1 GB） | ~5.0 GB（解压后约 6.5 GB） |
| **仿真/评分/SDK** | 完全相同 | 完全相同 |
| **可视化方式** | Three.js 浏览器自渲染（轻量） | Unreal Engine 离屏渲染 + 前端推流 |
| **三维画面质量** | 几何示意（地形网格 + 实体图元） | 真实 UE 渲染仿真视频流（接近真实无人机云台视角） |
| **是否需要安装 UE 编辑器** | 否 | **否**（包内已含打包好的 UE 运行时，开箱即用） |
| **GPU 要求** | 无（纯 CPU 可跑） | **必须**独立 GPU，显存 ≥ 8 GB，支持 Vulkan（无 GPU 或不满足时自动降级为 Three.js） |
| **硬件要求** | 一般开发机即可 | 显卡性能强、内存充足（推荐 16 GB+ 内存、RTX 级独显） |
| **额外内容** | — | 多出 `20260629-1523_Development/`（UE 打包产物）+ `config/renderers/ue_testwl.json`（已激活） |
| **照片保存（云台拍照）** | 不支持 | 支持（见 [§5.8](#58-ue-渲染截图保存-saveimage)） |

**如何选择？**

- **追求快速上手、轻量调试、或硬件一般** → 用标准版 `Simulation-1.1.1`。它能完成全部三道赛题的开发、调试与评分，可视化足以观察算法行为。
- **想看到真实渲染的三维仿真视频画面、或需要无人机云台拍照落盘** → 用 UE 增强版 `Simulation+UE-1.1.1`。它**不需要你安装 Unreal Engine 软件**，但要求参赛机器有较强的 GPU。
- 两个包可以**各自独立使用**，也可以都下载：先用标准版快速迭代算法，再用 UE 版做最终可视化验证。

> ⚠️ UE 增强版解压后体积较大（~6.5 GB），请确保目标磁盘有 **≥ 15 GB** 可用空间（含运行时日志与截图）。

### 2.2 系统要求

**Linux x86-64**：
- **操作系统**：Linux x86-64，glibc ≥ 2.39（**Ubuntu 24.04+** 推荐；Ubuntu 22.04 及更早版本 glibc 版本不足，引擎二进制无法运行）。
- **包管理器**：apt（`setup.sh` 用其自动装 `python3`/`lsof`/`curl` 等系统依赖；非 Debian/Ubuntu 系统需手动装）。
- **Python**：3.10+，需 `redis`、`pyyaml` 包（`setup.sh` 会自动 `pip install --user`）。
- **Node.js / Redis**：**无需预装**——两个包均已内置 Node.js v22 与 Redis 7.4.2（在 `bin/` 下）。
- **GPU**：仅 UE 增强版需要（≥ 8 GB VRAM、Vulkan）；标准版纯 CPU 即可。

**Windows x64**：
- **操作系统**：Windows 10 1809+ 或 Windows 11（需内置 tar/curl 和 PowerShell 5.1+）。
- **Python**：3.10+（从 https://www.python.org/downloads/ 安装，安装时勾选 "Add Python to PATH"；或用 `winget install Python.Python.3.12`）。
- **Node.js / Redis**：**无需预装**——包内置 `bin\node.exe`（Node.js v22）与 `bin\redis-server.exe`（redis-windows-fork）及依赖 DLL。
- **GPU**：仅 UE 增强版需要；标准版纯 CPU 即可。


### 2.3 一键启动

解压后，在**包根目录**（含 `start.sh` 的那一层）依次执行：

```bash
tar xzf Simulation-1.1.1-linux-x64.tar.gz      # 或 Simulation+UE-1.1.1-linux-x64.tar.gz
cd Simulation-1.1.1-linux-x64/                   # 进入包根目录

./setup.sh     # 1. 环境检测 + 自动安装依赖（仅需一次，可能要求 sudo）
./start.sh     # 2. 启动 Redis + bridge + 前端（浏览器会自动打开）
./verify.sh    # 3.（可选）健康检查，确认各组件就绪
./stop.sh      # 4. 用完后停止所有进程（含 UE 孤儿兜底清理）
```

```powershell
# Windows (PowerShell)
.\setup.ps1     # 1. 环境检测 + 自动安装 Python 依赖（无需管理员权限）
.\start.ps1     # 2. 启动 Redis + bridge + 前端（浏览器会自动打开）
.\verify.ps1    # 3.（可选）健康检查，确认各组件就绪
.\stop.ps1      # 4. 用完后停止所有进程
```

各脚本职责：

| 脚本 | 作用 | 何时运行 |
|---|---|---|
| `setup.sh` / `setup.ps1` | 检测并安装缺失的依赖（Linux: `lsof`/`curl`/`procps`/`python3`/`pip`；Windows: `python`/`pip`）和 Python 包（`redis`/`pyyaml`）。**幂等**，可重复运行。 | 首次使用前运行一次；换机器后重跑 |
| `start.sh` / `start.ps1` | 启动三类常驻进程：① Redis（纯内存模式）② bridge（WebSocket + 相机帧 HTTP 服务，负责 spawn 引擎与 UE）③ 前端静态服务。**端口被占会自动顺延**到下一个空闲端口；启动后自动打开浏览器。 | 每次开始使用时 |
| `verify.sh` / `verify.ps1` | 健康检查：逐项探测 Redis / bridge HTTP / 前端 / Python 依赖 / 引擎二进制是否就位，输出 `✓/✗` 与通过/失败计数。 | 启动后排查问题；或怀疑环境异常时 |
| `stop.sh` / `stop.ps1` | 停止全部进程（前端 → bridge → competition/引擎 → UE → Redis），含 UE 孤儿进程兜底清理。**幂等**。 | 每次用完或要重启时 |

> 💡 `start.sh` **只启动前端基础设施**（Redis + bridge + 前端），**不**预启动仿真引擎——引擎是在你于前端界面点击「开始仿真」时，由 bridge 按需 spawn 的（加载约 786 MB 地形需 ~15 秒）。

> 💡 `start.ps1`（Windows）功能相同——只启动前端基础设施，不预启动仿真引擎。

**端口配置**（默认值，被占用会自动顺延；也可用环境变量指定）：

| 环境变量 | 默认 | 用途 |
|---|---|---|
| `OPENSIM_REDIS_PORT` | 6379 | Redis |
| `OPENSIM_WS_PORT` | 8080 | bridge WebSocket |
| `OPENSIM_CAM_PORT` | 8081 | bridge HTTP（相机帧 + sim 控制 API） |
| `OPENSIM_WEB_PORT` | 3000 | 前端静态服务（浏览器访问地址） |

```bash
# 示例：指定端口启动（无头服务器可加 OPENSIM_NO_OPEN_BROWSER=1 不开浏览器）
OPENSIM_WEB_PORT=3001 OPENSIM_NO_OPEN_BROWSER=1 ./start.sh
```

```powershell
# Windows 示例：指定端口启动
$env:OPENSIM_WEB_PORT = '3001'; $env:OPENSIM_NO_OPEN_BROWSER = '1'; .\start.ps1
```

### 2.4 界面操作：选赛题 → 开始仿真

`start.sh` 成功后浏览器会打开 `http://localhost:3000/`（或顺延端口）。界面操作：

1. **选赛题**：在右侧「赛题选择」面板点击三道赛题之一（`search_track` / `coop_decoy` / `adversarial_swarm`），选中项高亮。
2. **开始仿真**：点击「**开始仿真**」按钮 → bridge 自动 spawn 引擎（加载地形约 15 秒）→ 加载该赛题对应的**内置示例算法（baseline）**→ 开始推演。状态栏显示 `running`，进度条显示仿真进度。
3. **暂停 / 恢复**：点击「暂停」可冻结推演（再点恢复）；便于观察中间态势。
4. **关闭仿真**：点击「关闭仿真」结束当前会话，释放引擎与 UE 进程；之后可选别的赛题再开。
5. **查看评分**：界面左上角圆形总分按钮 → 展开各维度条形图（实时 ~10Hz 刷新）。
6. **接入自己的算法**：见 [§5.2](#52-接入你自己的算法)。

> 默认情况下，前端用每道赛题的**内置示例算法**跑（赛题一 `search_track_fsm`、赛题二 `coop_distributed`、赛题三 `swarm_distributed`）。这三套 baseline 已能完整跑通赛题，可作为你算法的对照基线。

### 2.6（可选）从源码构建

## 三、三道赛题

三道赛题是**难度递进的阶梯**：单机入门 → 多机协同进阶 → 对抗集群高阶。

### 赛题一 · 单机搜索跟踪（入门）

| 项 | 内容 |
|---|---|
| **名称** | `search_track` — 无人机搜索与跟踪小车 |
| **你控制** | **1 架** UAV（带云台相机） |
| **环境** | 1 辆移动的真实目标车 |
| **威胁** | 无 |
| **协同** | 无（单机） |
| **默认时长** | 600 s（10 分钟） |
| **可用命令** | `fly_to` / `set_heading` / `set_speed` / `point_gimbal` / `set_gimbal_fov` / `report_target` |

**任务背景**：单架无人机被投送到任务区，需在 600 秒内自动搜索并持续跟踪一辆地面移动小车。目标是**持续、准确地把小车位置报出来**。

**任务目标**：实现 `搜索 ↔ 跟踪` 自动状态机——未发现目标时驱动无人机 + 云台协同搜索（螺旋/栅格扫描）；发现后跟住小车、估准它的坐标，并**每秒**用 `report_target(lat, lon)` 上报位置。

**关键规则**：
- 平台会在 `obs.briefing.target_initial_pos` 中**给出目标初始位置**（这是三题中唯一给目标位置的一题，作为入门辅助）。
- 无诱饵、无通信、无威胁区。
- 评分依据你的 `report_target` 上报（持续目指精度）：每秒采样，按上报点离真值的距离软命中打分（D_max=30m），漏报拍记 0 分，每 20s 窗口去掉 2 个最低分。详见 [§4.4](#赛题一单维度)。

### 赛题二 · 多机协同识别（进阶）

| 项 | 内容 |
|---|---|
| **名称** | `coop_decoy` — 多无人机协同通信与抗干扰识别 |
| **你控制** | **3 架** UAV 中的一架（每架独立 Agent 实例） |
| **环境** | 3 辆移动的真实目标车 + **15 辆静止诱饵车** |
| **威胁** | 无 |
| **协同** | 受限通信（广播 + 点对点） |
| **默认时长** | 600 s（10 分钟） |
| **可用命令** | 全部 UAV/云台命令 + `broadcast` / `send_to` / `report_target` |

**任务背景**：3 架无人机分散部署，面对**分散分布的 3 个真目标 + 15 个诱饵**。诱饵进入相机视场时按 **~50% 概率被误识别为真目标**，诱导你的算法误跟踪。

**任务目标**：
- **协同搜索**：多机基于通信减少重复覆盖，尽快发现所有真目标。
- **协同识别**：判断干扰目标和真实目标，靠**多帧运动学一致性**区分（见 [§6.2 诱饵伪装](#detection--本拍检测结果)）。
- **协同盯防打击**：≥2 架 UAV 同时盯防同一真目标累计 20 秒即**判定摧毁目标**。
- **目指上报**：用 `report_target(lat, lon)` 上报判定为真目标的位置，按定位精度（RMSE）评分。

**通信约束**（引擎强制，详见 [§6.3](#通信仅赛题二三赛题一无队友)）：

| 约束 | 限制 |
|---|---|
| 通信距离 | ~1000 m（超距：点对点失败有反馈，广播静默丢弃无反馈） |
| 单消息字节 | ≤ 50 字节（超出抛 `PayloadTooLarge`） |
| 发送频率 | ≤ 4 Hz（滑窗节流） |
| 收件箱容量 | 32 条 |

**默认时长**：600 s（10 分钟）。

**关键规则**：
- **不再给目标位置**（`target_initial_pos = None`），但给 `target_count = 3`。
- 无诱饵识别能力——必须靠运动学判别。
- 通信是你与队友**唯一**的协同途径（数据层强制信息隔离，见 [§6.4](#64-信息隔离核心防作弊机制)）。

### 赛题三 · 对抗集群搜索（高阶）

| 项 | 内容 |
|---|---|
| **名称** | `adversarial_swarm` — 博弈对抗条件下的无人机群协同搜索 |
| **你控制** | **10 架** UAV 中的一架 |
| **环境** | 10 辆移动真目标 + **20 辆静止诱饵** |
| **威胁** | **防空区（SAM）+ 静态通信干扰区 + 动态随机干扰区** |
| **协同** | 通信（复用赛题二）+ 分布式拍卖 |
| **默认时长** | 600 s（10 分钟） |
| **可用命令** | 全部 UAV/云台/通信/上报命令 |

**任务背景**：10 架无人机群面对**高对抗场景**——除了 20 个诱饵干扰，还有：

1. **防空区（SAM air-defense zone）**：无人机进入防空区并滞留 ≥ 2 秒，**必然被击毁**（`hit_probability = 1.0`）。被击毁的无人机从战场永久消失。
2. **静态通信干扰区**：无人机落入即通信失效，离开自动恢复。
3. **动态随机干扰区**：随时间随机生成/消失的干扰区，位置事先未知。

**任务目标**：在**尽可能降低被击毁数量**的同时，搜索、识别并盯防摧毁尽可能多的真目标。要求**分布式**算法：
- 失联节点（被击毁）的跟踪任务由**分布式拍卖**重新分配，最高价者中标接管。
- 通过**失联队友的最后心跳位置 + 安全半径**推测威胁点，做盲规避。
- 干扰区导致通信中断时各机独立运行不报错。

**威胁感知模型**（核心对抗设计 —— "已知 = 简报，未知 = 感知 + 共享"）：

| 威胁 | 你如何知道它 |
|---|---|
| SAM 防空区（静态） | `briefing.approximate_zones`（仅给**近似外接矩形 + 面积 + 高度带**，外扩约 20%，**无精确多边形**）。规避方式：**只能水平绕行**（高度全程锁定 500m，SAM 高度带 [0, 2500m] 无法爬升越过，见 [§6.2.5](#625-uav-平台物理参数平台给定不可改)） |
| 静态干扰区（静态） | `briefing.approximate_zones` |
| 随机干扰区（动态） | `obs.self.jammed` 翻为 `true` 时**自行估计位置**，再 `broadcast("J:lat,lon")` 警告队友 |

> ⚠️ **严格信息隔离**：你的算法**禁止读取**场景的 `zones` 配置、`sim:state` 中的 `zones` 字段、以及其他实体的 `status`。这些属于"上帝视角"，违规即作弊。你只能读：本机 `obs.self`、本机 `detection`、通信收件箱 `obs.comm_inbox`、静态简报 `obs.briefing`。

**关键规则**：
- 地图边界（真实地形，即 `HeightSample.csv` 覆盖区）：约 4.8 km × 4.0 km，纬度 26.9818–27.0250、经度 124.9800–125.0203。**威胁区（SAM/干扰区）的生成与裁剪以此地形边界为准**，不会落到真实地图之外。UAV 飞出此边界 500m 以内不扣分，超出 500m 才计入越界减分（见 §4.6）。
- 给 `target_count = 10` 和 `approximate_zones`，但**不给动态威胁位置**。
- **没有 `attack` 命令**——杀伤靠区域裁决（SAM）或盯防达成（20s），你只能规避或盯防。
- 你的 UAV 若被击毁（`obs.self.status == "destroyed"`），runner 自动停止调用你的 `decide()`，无需处理。

## 四、评分体系

### 4.1 评分输出

- **发布频率**：**~10 Hz 实时评分**（每个控制周期一帧），运行结束时再发一帧 `final`。
- **前端展示**：可视化界面左上角的评分面板（圆形总分按钮 → 展开各维度条形图）。
- **结果落盘**：`output/<run>.evaluation.json`（末帧完整评估）。

末帧评分 JSON 的核心字段：

```jsonc
{
  "final": true,                // 是否末帧
  "sim_time": 12.3,             // 仿真时间（秒）
  "total_score": 73.5,          // 总分 0–100
  "dimension_scores": {         // 各维度子分 0–100
    "kill": 66.7,
    "accuracy": 80.0,
    "misid_penalty": 90.0
  },
  "kill_rate": 0.667,           // 击毁率
  "alive_rate": 1.0,            // 存活率（仅赛题三）
  "per_target": { ... }         // 每个真目标状态
}
```


### 4.2 三大核心机制

赛题二、三共享以下三个机制（赛题一无打击能力，仅评**持续目指精度**——见 [§4.4](#赛题一单维度)）：

1. **盯防摧毁（destroy）**：≥ K 架 UAV **同时**对**同一真实目标**连续有效跟踪累计满 `dwell_target_s`（默认 20s）→ 该目标被判定摧毁，永久锁定。短暂中断 ≤ `grace_s`（2s）不清零且会回补；中断 > 2s 清零重来。**协同阈值 K 由各赛题 runner 在运行时注入：赛题二 K=2、赛题三 K=3**（即分别需 2 架 / 3 架同时盯防满 20s）。继续跟踪已摧毁目标不计入得分。
2. **诱饵识别（identify）**：诱饵被 ≥ K 架 UAV 连续跟踪满 20s → 被识别，此后不再计入误识别惩罚。
3. **目指上报（accuracy）**：Agent 用专用接口 `report_target(lat, lon)` 上报，评分器按 per-target 独立考核——每个真目标分别计算其上报的 RMSE 得出子分 `acc_t = 100×(1−RMSE_t/D_max)`，最终 accuracy 为**全部真目标（含已摧毁）子分的算术平均**；**从未上报的目标 acc_t = 0 计入平均**。每秒每目标最多记 1 次（按裁判解析的目标计，与传入的 `target_id` 标签无关）。上报点若离已摧毁目标更近（即报"尸体"）则整条丢弃，不计入任何目标。**口径要点**：每目标在**整个运行期间**累计 RMSE；目标被摧毁后，对其的新上报被丢弃（RMSE 冻结在摧毁时刻），但摧毁前样本仍计入其子分、且该目标仍留在分母里（摧毁不把它移出平均）。

### 4.3 通用总分公式

```
base_score  = clamp( Σ ( weight_k × dimension_score_k ), 0, 100 )
total_score = clamp( base_score − penalty, 0, 100 )
```

每个维度独立计 0–100 分，按 profile 权重加权求和得到 `base_score`。
赛题二/三另有**后置减分项** `penalty`（见 [§4.6](#46-减分项仅赛题二三)），
从 `base_score` 中扣除得到最终 `total_score`。减分项**不参与权重比例**，
且 `passed`（是否达标）按 `base_score` 判定——减分只影响排名，不影响达标。

各维度的计分公式：

| 维度 | 公式 |
|---|---|
| `accuracy`（赛题一） | `100 × (Σ 未剔除拍 p_t / 未剔除拍数)`，每拍 `p_t = clamp(1 − D_t/30, 0, 1)`，1Hz 采样上报点离真值距离 D_t，漏报拍 p_t=0，每 20s 窗口去掉 2 个最低 p_t |
| `kill` | `100 × 击毁真目标数 / 真目标总数` |
| `accuracy`（赛题二/三） | 每目标全程累计：`acc_t = 100 × max(0, 1 − RMSE_t / D_max_m)`，`RMSE_t = √(该目标累计误差²和 / 上报次数)`；未上报目标 acc_t=0；目标摧毁后停止采集其新样本（冻结在摧毁时刻），但摧毁前样本仍计入、分母=全部真目标数（含已摧毁）；最终 = 所有目标 acc_t 的平均 |
| `mission_time` | `T_done ≤ T0 → 100`；`T0 < T_done ≤ T0+T_flex → 线性衰减到 0`；未全歼或超时 → 0 |
| `alive` | `100 × 存活 UAV 数 / 初始 UAV 数` |



### 4.4 赛题各自评分维度


#### 赛题一（单维度）

| 维度 | 权重 | 说明 |
|---|---|---|
| `accuracy`（持续目指精度） | **1.0** | 1Hz 上报目标坐标，按 `p_t = clamp(1 − D_t/D_max, 0, 1)` 软命中打分，漏报拍 p_t=0，每 20s 窗口去掉 2 个最低分（D_max=30m） |

#### 赛题三（4 维，含生存）

### 4.5 评分要点提示

- **盯防即摧毁，无需开火**：把 UAV 持续对准真目标 20 秒即可摧毁（赛题二 K=2 需 2 架同时盯防；赛题三 K=3 需 3 架同时盯防）。策略重点是**稳定跟踪**而非火力。
- **上报要勤但别浪费**：`report_target` 每目标每秒只记 1 次；对已摧毁目标的上报会被忽略，应及时切换。
- **诱饵不影响得分**：诱饵误判惩罚已移除，误跟踪诱饵不再扣分（识别状态机仍作诊断运行）。但诱饵会占用盯防时间，间接拖慢 mission_time。
- **赛题三 SAM 规避只能水平绕行**：高度全程锁定 500m（见 [§6.2.5](#625-uav-平台物理参数平台给定不可改)），SAM 高度带 [0, 2500m] 无法爬升越过，**必须在水平方向上绕开 SAM 区域**。
- **避免过近与越界**（赛题二/三）：两架 UAV 水平距离 <200m、或飞出地形边界 >500m 都会扣分，见 [§4.6](#46-减分项仅赛题二三)。

### 4.6 减分项（仅赛题二、三）

赛题二、三在加权总分 `base_score` 之外，另有两项**后置减分**，从 `base_score`
中扣除得到 `total_score`。减分项**不计入权重比例**，且 `passed`（是否达标）
按 `base_score` 判定——减分只影响排名，不影响达标。

| 减分项 | 触发条件 | 单次扣分 | 说明 |
|---|---|---|---|
| **飞机过近** | 两架 UAV 水平距离 `< 200m` | 2 分 | 每进入一次该状态扣一次（边缘触发）；持续接近不计；分开后再接近再扣 |
| **越界** | UAV 飞出地形边界 `> 500m` | 2 分 | 每进入一次该状态扣一次（边缘触发）；地形边界=纬度 26.9818–27.0250、经度 124.9800–125.0203（约 4.8×4.0 km，即 `HeightSample.csv` 覆盖区，运行时由该 CSV 派生） |

- **总扣分上限 15 分**（两项合计）。
- **边缘触发**：以"进入违规状态"为计数单位，对仿真拍频（60Hz）鲁棒——持续违规只计 1 次，离开后再次进入才计第 2 次。
- **被摧毁的 UAV 不触发**这两项（坠毁机体不再计）。
- 评分输出含 `base_score`、`penalty`、`penalty_breakdown`（含 proximity/boundary 各自计数与单次扣分）。

### 5.1 推荐流程：界面一键运行

```bash
cd Simulation-1.1.1-linux-x64/        # 或 Simulation+UE-1.1.1-linux-x64/

# 1. 首次运行：检测并安装依赖（仅需一次）
./setup.sh

# 2. 启动 Redis + bridge + 前端（浏览器自动打开 http://localhost:3000）
./start.sh

# 3. 在浏览器界面：选赛题 → 点「开始仿真」
#    （默认用该赛题的内置示例算法，可直接观察 baseline 表现）

# 4. 用完停止
./stop.sh
```

```powershell
# Windows (PowerShell)
.\setup.ps1
.\start.ps1
# 浏览器自动打开 http://localhost:3000
# 在界面：选赛题 → 点「开始仿真」
.\stop.ps1
```

界面启动后，你点「开始仿真」时，bridge 会自动：spawn 引擎 → 连 Redis → 加载场景 → 以该赛题默认的 baseline 算法运行 → 实时评分 → 评分落盘到 `output/`。

### 5.2 接入你自己的算法

界面默认跑的是三套**内置示例算法（baseline）**，仅供对照。要校验/运行你自己的算法，有两种方式：

**方式 A —— 命令行运行（最直接，推荐开发调试用）**

把你的 Agent 文件放到包根目录（或设 `PYTHONPATH` 包含其所在目录），然后用 `python -m competition run` 指定 `--agent`：

```bash
# 1. 在包根目录写一个 agent（参考 competition/baselines/ 下的实现）
#    my_agent.py
from competition.sdk.scenarios.search_track import SearchTrackAgent
from competition.sdk.core.commands import fly_to, point_gimbal

class MyAgent(SearchTrackAgent):
    def decide(self, obs, dt):
        if obs.self.detection.detected:
            return [point_gimbal(0.0, -45.0),
                    fly_to(obs.self.detection.target_lat,
                           obs.self.detection.target_lon)]
        return [fly_to(obs.self.lat + 0.001, obs.self.lon),
                point_gimbal(0.0, -45.0)]

# 2. 命令行运行（需先 ./start.sh 起好 Redis；或自带 --start-sim）
PYTHONPATH=. python -m competition run --scenario search_track \
    --agent my_agent:MyAgent --duration 600 --start-sim --visualize
```

**方式 B —— 界面选择算法**

当前 release 包的前端界面支持「算法」输入框。在选赛题后，于「算法」框中填入 `module:Class`（如 `my_agent:MyAgent`），再点「开始仿真」即可加载你的算法。留空则使用该赛题的内置 baseline。

> 无论哪种方式，`--agent` 接受 `module:Class` 形式。内置示例算法可用简写：
> - 赛题一：`baselines.search_track_fsm:FsmAgent`
> - 赛题二：`baselines.coop_distributed:CoopDistributedAgent`
> - 赛题三：`baselines.swarm_distributed:SwarmDistributedAgent`

### 5.3 命令行运行（进阶）

## 六、参赛 SDK API 参考

> 本节是接口的权威参考。参赛接口面非常小：**你写一个类、实现一个方法**。

### 6.1 Agent 基类与生命周期

```python
class Agent(ABC):
    def __init__(self, my_uid: str): ...        # runner 传入本实体 unique_id
    def configure(self, config) -> None: ...    # 可选；注入静态任务参数
    def reset(self) -> None: ...                # 可选；每局首次 decide 前调用
    @abstractmethod
    def decide(self, obs, dt: float) -> list[Command]: ...  # 必须实现；~10Hz 调用
```

| 成员 | 调用时机 | 你要做什么 |
|---|---|---|
| `__init__(my_uid)` | 启动一次 | 存下来；它就是你要控制的实体 |
| `configure(config)` | 运行前一次 | 可选；读取静态任务参数 |
| `reset()` | 每局首个 `decide()` 前 | 可选；清空内部状态 |
| `decide(obs, dt)` | 每个决策周期（~10Hz） | **必须实现**；返回给 `my_uid` 的命令列表 |

**5 个不变量**（务必遵守）：

1. `decide()` 除 `self` 内部状态外是**纯函数**——不直接读写 Redis/文件/网络。
2. 返回的命令列表**按序发布**，顺序敏感。
3. 命令**只作用于 `self.my_uid`**——runner 发布时强制注入 `unique_id = my_uid`，你**无法越权控制其他实体**。
4. 返回空列表 `[]` 表示本周期不发命令。
5. 赛题三中你的 UAV 若被击毁（`obs.self.status == "destroyed"`），runner 自动停止调用 `decide()`，无需处理。

### 6.2 观测模型（`obs`）

`decide(obs, dt)` 每次给你的 `obs` 是固定三字段结构（**永不增删**）：

```python
obs.self:        SelfView              # 本机可物理感知的自身状态
obs.comm_inbox:  tuple[Message, ...]   # 本周期收到的队友消息
obs.briefing:    MissionBriefing       # 赛前已知静态信息（整局不变，score_view 除外）
```

#### `SelfView` — 本机自身状态

| 字段 | 类型 | 含义 |
|---|---|---|
| `uid` | str | 本机 unique_id（= `agent.my_uid`） |
| `lat` / `lon` / `alt` | float | WGS84 位姿（**`alt` 全程恒为 500m**，见 [§6.2.5](#625-uav-平台物理参数平台给定不可改)） |
| `heading_deg` | float | 航向（度） |
| `speed` | float | 速度（m/s） |
| `gimbal_pan` / `gimbal_tilt` | float | 云台方位/俯仰（度） |
| `gimbal_fov_deg` | float | 相机视场角（度） |
| `detection` | `Detection` | 相机检测结果 |
| `status` | str | `"active"` / `"destroyed"` |
| `jammed` | bool | **本机当前是否被通信干扰**（动态威胁唯一合法感知入口，仅赛题三） |
| `comm_stats` | `CommStats` | 本机通信统计 |
| `photo` | `Optional[bytes]` | UE 渲染最新相机帧 **PNG bytes**（默认自动注入，无帧为 `None`；详见 [`obs.self.photo`](#obsselfphoto--ue-渲染相机帧默认自动可用)） |

#### `Detection` — 本拍检测结果

| 字段 | 含义 |
|---|---|
| `detected` | bool；是否有目标在相机视场内 |
| `confidence` | [0,1]；越居中越高 |
| `target_lat` / `target_lon` | 检测到的位置（**可能是诱饵误识别，不是真值**） |
| `azimuth_error_deg` | 相对光轴的方位偏移（度） |
| `target_type` | `"ground_vehicle"` 或 `""` |

> ⚠️ **诱饵伪装**：相机被诱饵骗到（~50% 概率）时，`target_type` 仍报 `"ground_vehicle"` —— 你**无法靠类型字段识破诱饵**。诱饵是**静止**的、真目标是**移动**的，必须靠**多帧运动学一致性**判别（参考实现 `competition/baselines/swarm_distributed.py`）。
>
> 🎨 **关于"车型/颜色"**：在 UE 增强版的渲染画面里，真目标与诱饵外观（车型、涂装颜色，且颜色接近）有视觉区别。但这个区别**只存在于渲染画面中，代码层完全读不到**——`Detection` 里没有任何车型/颜色字段。除非你用 `--mode eval` 接入自研 YOLO 感知去识别渲染图像，否则无法利用该视觉差异；判别诱饵**只能靠上面的运动学方法**。

#### `Message` — 队友通信

| 字段 | 含义 |
|---|---|
| `sender_uid` | 发送者 uid（**不给发送方位姿**） |
| `payload` | ≤50 字节字符串，**格式参赛者自定义** |
| `recv_time` | 接收时刻（sim_time） |

#### `MissionBriefing` — 赛前静态简报（可扩展，字段只增不删）

| 字段 | 含义 | 赛题一 | 赛题二 | 赛题三 |
|---|---|---|---|---|
| `self_uid` | 本机 uid | ✓ | ✓ | ✓ |
| `fleet_size` | 编队受控实体总数 | 1 | 3 | 10 |
| `mission_area` | 任务区域边界 | ✓ | ✓ | ✓ |
| `target_initial_pos` | 目标初始 (lat,lon) | **✓ 给** | ✗ | ✗ |
| `target_count` | 目标数量 | (隐含=1) | **✓ 给（3）** | **✓ 给（10）** |
| `approximate_zones` | 近似威胁区（bbox+面积+类型+高度带，外扩~20%，**无精确多边形**） | ✗ | ✗ | **✓ 给** |
| `params` | 白名单参数（如 `coop_k`、动态干扰区统计 max_count/radius/lifetime，**不含位置**） | ✓ | ✓ | ✓ |
| `score_view` | 每拍实时得分快照（首拍 `None`） | ✓ | ✓ | ✓ |

> 注：`known_threats` 字段**已废弃**，恒为 `()`。赛题三改用 `approximate_zones`。

#### 感知层：默认识别器与运行模式（没写感知算法会怎样）

`obs.self.detection` 的来源由「感知层」决定。**感知层是可选的**——你不实现时平台用默认识别器替你检测，照样能参赛。

- **决策层**（必须）：`decide(obs, dt)` —— 解析 `obs`、返回控制命令。
- **感知层**（可选）：`sensor(obs, dt)` —— 自研检测。**不实现 / 返回 `None`** → 走**默认识别器**；返回 `List[Detection]` → 用你的结果；返回 `SKIP_DETECTION` → 端到端跳过；抛异常 → 容错回退默认识别器。

**默认识别器 `AccuracySimulator`（train 模式）**：不真识别，而是按概率从引擎几何真值采样 + 加噪：
- 检出概率 `accuracy`（默认 **0.85**，上限钳制 **0.9**）：目标在视场内时每拍按此概率伯努利检出。
- 位置噪声 `noise_sigma_m`（默认 **50 米**，下限钳制 **30 米**）：命中时给真值位置叠加高斯噪声——你拿到的坐标平均偏 σ 米。
- 诱饵在传给识别器前已被引擎按概率伪装成 `ground_vehicle`，所以默认识别器也会被骗。

> 钳制 accuracy≤0.9、noise≥30m 是为杜绝"检出概率 1.0 且噪声 0 → 位置退化等于真值"的作弊。

**两种运行模式（`--mode`）**：

| 模式 | 默认识别器 | 命令行参数 | 说明 |
|---|---|---|---|
| `train`（默认） | AccuracySimulator | `--accuracy 0.85 --noise-sigma 50` | 概率采样 + 噪声，开发调试用，无需 GPU |
| `eval` | YoloDetector | `--yolo-model <路径>` | 真实 YOLOv8 识别 UE 渲染图；默认 `--photo-mode auto` 自动提供相片帧；无帧时自动降级回 AccuracySimulator |

> 💡 **多数选手不需要写感知算法**：用默认 train 模式（带 ~50m 噪声、85% 检出、会被诱饵骗的检测）就能写完整的决策算法。想要更高精度可多帧滤波压噪声，或上 `--mode eval` 自研 YOLO。

#### `obs.self.photo` — UE 渲染相机帧（默认自动可用）

`obs.self.photo` 是本机相机最新一帧的渲染图，**带 UE 渲染端的标准运行环境里默认自动可用，无需任何开关或参数**。SDK 会把 UE 写入 Redis 的最新帧自动注入——**你在网页上能看到某架无人机的相机画面时，代码里 `obs.self.photo` 就能拿到同一帧**。

**图片格式是 PNG（不是 JPEG）**。解码示例：

```python
import numpy as np
import cv2

def decide(self, obs, dt):
    if obs.self.photo is None:
        return []  # 本帧无画面，务必先判空
    # cv2.imdecode + IMREAD_COLOR 会自动嗅探格式，PNG/JPEG 都能解
    img = cv2.imdecode(np.frombuffer(obs.self.photo, np.uint8), cv2.IMREAD_COLOR)
    # ... 你的视觉推理 ...
```

或用 Pillow：`Image.open(io.BytesIO(obs.self.photo))`。**不要按 JPEG 解析**（不要用 `cv2.IMREAD_JPEG`）。

> ⚠️ **务必先判空**：以下任一情况 `obs.self.photo` 为 `None`（正常降级，不是错误）：
> 1. `dry_run` 模式（无 UE 渲染）；
> 2. 显式设了 `--photo-mode off`；
> 3. UE 还没给当前这架无人机分配渲染——**多机赛题（赛题二 3 机 / 赛题三 10 机）受 UE 单架 assign 与带宽约束，未渲染的无人机会拿到 `None`**；
> 4. Redis 里暂时还没有该机的帧（刚启动、帧还没产生）。

**两种典型用法**：

```python
# 用法 A：自研感知——覆盖 sensor()，返回检测结果
def sensor(self, obs, dt):
    photo = obs.self.photo          # PNG bytes（默认自动注入）
    if photo is None:
        return None                 # 无帧 → 回退默认识别器
    boxes = self.my_model.detect(photo)
    return [Detection(detected=True, confidence=b.conf,
                      target_lat=b.lat, target_lon=b.lon) for b in boxes]

# 用法 B：端到端——跳过默认识别器，直接在 decide() 用图
def sensor(self, obs, dt):
    return SKIP_DETECTION           # 端到端：不跑默认识别器

def decide(self, obs, dt):
    photo = obs.self.photo
    if photo is None:
        return []
    action = self._policy(photo)
    return [action.to_command()]
```

> 📖 相机帧拉取的 CLI 开关（`--photo-mode {auto|on|off}` 三态）见 [§5.4](#54-常用-cli-参数)；旧参数（`--photo`/`--no-photo`）的迁移说明见 [`UPDATE-相机流自动启用.md`](UPDATE-相机流自动启用.md)。

### 6.2.5 UAV 平台物理参数（平台给定，不可改）

你的 UAV 是一架**固定翼无人机**。下面这些物理参数由平台在场景配置里**写死**，**你只能读、不能改**——你的 Agent 代码在赛前接触不到、也无法修改这些初始配置；运行中部分参数可以通过控制命令间接调整，但**调整区间也由平台限定**。

| 参数 | 取值 | 是否可改 | 说明 |
|---|---|---|---|
| **起始高度** | **500 m** | ❌ **不可改（全程锁死）** | 开局即 500m，**运行中也无法改变高度**（详见下方提示） |
| 起始位置（经纬度） | 各赛题投送点给定 | ❌ 不可改 | 由平台投送点决定，三题不同 |
| 起始航向 | 各赛题场景给定 | ⚠️ 初始值不可改 | 运行中可用 [`set_heading`](#uav-导航所有赛题) 改变 |
| 起始速度 | 20 m/s | ⚠️ 初始值不可改 | 运行中可用 [`set_speed`](#uav-导航所有赛题) 改变，但盘旋阶段会被覆盖（见下方提示） |
| 合法速度区间 | **15–40 m/s** | ⚠️ 区间不可改 | 超出范围被引擎**静默钳位**到区间内 |
| 最大转向率 | 平台限定 | ❌ 不可改 | 决定你转弯的快慢，航向指令受此限制 |
| 默认盘旋半径 | 200 m | ⚠️ 可在 `fly_to` 中指定 | 必须 >0 |
| 机型 | 固定翼 UAV | ❌ 不可改 | 三题统一，无直升机/多旋翼可选 |
| 云台视场角(FOV) | 初始 30° | ⚠️ 区间 **5–50°** 可调 | 上限 50° 为赛规（详见 [`set_gimbal_fov`](#云台--相机所有赛题这是核心感知接口)） |

> ⚠️ **高度全程锁定 500m —— 这是本竞赛的关键约束**：
>
> - `fly_to` 命令的 `alt` 参数**当前不生效**：无论你传什么高度值，引擎都会忽略，UAV **始终在 500m 飞行**。
> - 你的 `obs.self.alt` 在整局中**恒为 500**，是个不动点。
> - **赛题三的 SAM 防空区高度带是 [0, 2500m]**，500m 正落在击落区间内——因此**你无法通过爬升来规避 SAM**（"爬到 SAM 顶之上"这条路走不通）。规避 SAM **只能靠水平方向绕行**（见 [§4.5](#45-评分要点提示) 和 [§赛题三](#赛题三--对抗集群搜索高阶)）。
>
> 简言之：**高度维度不参与决策**，你的算法只需在水平面（经纬度）上规划航迹与规避。

> ⚠️ **速度可改，但盘旋阶段会被强制覆盖为 20 m/s**：
>
> - 速度**有两个接口，且能真正改变**：[`set_speed(speed)`](#uav-导航所有赛题)（单独调速，维持当前航向）和 [`fly_to(..., speed=)`](#uav-导航所有赛题)（设导航点时一并带速），合法区间 **15–40 m/s**，超出被引擎静默钳位。
> - **但有陷阱**：UAV 一旦进入**盘旋（loiter）或接近（approach）阶段**，引擎每帧会把目标速度**无条件重置为 20 m/s**，覆盖你 `set_speed` 设的值。开局即在投送点盘旋、`fly_to` 到达目标点后盘旋——这些时段你设的速度都**不生效**。
> - 因此 `set_speed` **只在非盘旋的直飞阶段持续生效**。若你的策略依赖固定巡航速度，需意识到盘旋段速度恒为 20 m/s。

### 6.3 控制命令

你**不直接构造命令 dict**，而是调用 `competition.sdk.core.commands` 的构造器函数，返回 `Command` 对象。runner 发布时强制 `unique_id = my_uid`。

#### UAV 导航（所有赛题）

```python
fly_to(lat, lon, alt=None, speed=None, loiter_radius=200.0, turn_direction="right")
#   引擎 verb: set_destination。导航到目标点并盘旋。
#   speed: 15–40 m/s（超范围被引擎静默钳位）；loiter_radius: >0；turn_direction: "right"/"left"
#   ⚠️ alt 参数当前不生效：高度全程锁定 500m（详见 §6.2.5），传任何 alt 值都会被忽略。
#   ⚠️ speed 仅在直飞段生效；进入盘旋/approach 后目标速度被强制覆盖为 20 m/s（详见 §6.2.5）。

set_heading(heading_deg)   # verb: set_heading
set_speed(speed)           # verb: set_speed，15–40 m/s（钳位）；⚠️ 盘旋/approach 阶段被覆盖为 20 m/s（详见 §6.2.5）
```

#### 云台 / 相机（所有赛题；这是核心感知接口）

```python
point_gimbal(pan_deg, tilt_deg)   # verb: component.gimbal_tracking.set_orientation
#   pan: -180~180（钳位），tilt: -90~90（钳位，下为负）。
#   pan=0, tilt=-45 是地面搜索默认（前视下视）。

set_gimbal_fov(fov_deg)           # verb: set_fov，5–120°（钳位）
#   宽 FOV 覆盖大但 confidence 低；窄 FOV confidence 高但覆盖小。
```

> **相机只在视场内检测目标**——必须先用 `point_gimbal` 瞄准，才能搜索/跟踪。这是 ISR 任务的核心。

#### 通信（仅赛题二、三；赛题一无队友）

```python
broadcast(payload: str)              # verb: comm.broadcast，≤50 字节
send_to(peer_uid: str, payload: str) # verb: comm.send，点对点
```

受引擎**四级限制**：字节（≤50）/ 速率（4Hz 滑窗）/ 距离（~1000m）/ 干扰区。被丢弃的消息你只能从 `obs.self.comm_stats.rejected_*` 间接感知。

#### 目标上报（三题都用，专用接口）

```python
report_target(lat, lon, target_id=None)   # verb: agent.report
#   你「判定真目标在 (lat,lon)」的意图信号。引擎不处理；runner 路由给评分器算精度。
#   限速 1 报告/目标/秒（按裁判解析的目标计，与 target_id 标签无关）；
#   对已摧毁目标的报告、以及报"尸体"（上报点离已摧毁目标更近）均整条丢弃。
```

> ⚠️ **目指上报只能用这个专用接口**，**不能**用 `broadcast`/`send_to` 通信消息替代——通信消息是给队友看的，评分器不收。赛题一靠它每秒上报驱动持续目指精度；赛题二/三靠它按每目标累计 RMSE 评分（详见 [§4.2](#42-三大核心机制) 第 3 条）。

#### 不存在的命令

- **没有 `attack` / `fire` / `launch`**：杀伤靠引擎区域裁决（SAM）或盯防达成（20s）。这是赛题设计意图，不是 SDK 缺陷。
- **没有 `deploy_decoy`**：诱饵是场景静态实体。
- **赛题一不含通信命令**（无队友），但**含 `report_target` 上报命令**——赛题一评分依赖选手每秒上报目标坐标（持续目指精度，见 [§4.4](#赛题一单维度)）。

### 6.4 信息隔离（核心防作弊机制）

这是 SDK 与普通仿真器最大的区别：构造每个 agent 的 `obs` 时**只读本实体**——其他实体的位姿/真值/检测结果**物理上不投影**（不是"有但不让读"）。

**你拿不到**：队友位姿、目标真值位置/轨迹、诱饵真值、动态干扰区位置、其他实体的检测结果。这些只能靠「感知 + 估计 + 通信同步」获得。

## 七、参考实现与进阶

### 7.1 参考实现（`competition/baselines/`）

强烈建议先跑通 baseline 对照，再写自己的 Agent。下面三条命令等价于在界面里选赛题后点「开始仿真」（界面默认用的就是这三套 baseline）。命令行运行时需先 `./start.sh` 起 Redis，并加 `--start-sim` 让 SDK 自动 spawn 引擎；或直接在已 `./start.sh` 的前端界面里选赛题点「开始仿真」：

```bash
# 赛题一参考：SEARCH↔TRACK 状态机
python -m competition run --scenario search_track \
    --agent baselines.search_track_fsm:FsmAgent --duration 600

# 赛题二参考：纯通信协同（uid 哈希分扇区 + 诱饵运动学判别）
python -m competition run --scenario coop_decoy \
    --agent baselines.coop_distributed:CoopDistributedAgent --duration 600

# 赛题三参考：分布式协同（避险 + 拍卖 + 目标共享上报）
python -m competition run --scenario adversarial_swarm \
    --agent baselines.swarm_distributed:SwarmDistributedAgent --duration 600
```

| Baseline | 演示的 SDK 能力 |
|---|---|
| `search_track_fsm.py` | 赛题一 FSM：用 `briefing.target_initial_pos` 先直飞再螺旋搜索；`fly_to` + `point_gimbal`。**完全不读目标真值** |
| `coop_distributed.py` | 赛题二纯通信协同：uid 哈希预分配扇区、`broadcast`/`send_to`、诱饵靠 detection 时序判别 |
| `swarm_distributed.py` | 赛题三分布式：`approximate_zones` 静态避险 + `obs.self.jammed` 动态感知；`broadcast("T:lat,lon")` 共享目标、`broadcast("J:lat,lon")` 警告干扰；`report_target` 上报 |

### 7.2 关键心智模型

1. **每次 `decide()` 只看三样东西**：`obs.self`（本机）+ `obs.comm_inbox`（队友消息）+ `obs.briefing`（静态简报）。看不到队友位姿、目标真值、动态威胁位置。
2. **协同永远走 `broadcast`/`send_to`**，绝不共享全局视图。建议与队友约定 payload 格式（如 `T:` = 目标、`J:` = 干扰、`R:` = 集合）。
3. **诱饵靠运动学判别**：连续多拍检测位置不变 → 大概率诱饵，应离开。
4. **盯防即摧毁**：对真目标持续盯防 20s 即可摧毁，无需开火（赛题二需 **2 架**同时、赛题三需 **3 架**同时——即 K）。
5. **赛题三避险约定**：高度全程锁定 500m（见 [§6.2.5](#625-uav-平台物理参数平台给定不可改)），无法爬升越过 SAM 高度带 [0, 2500m]，规避 SAM **只能靠水平方向绕行**。

## 附录 A：常见问题

**Q1：我看不到队友的位置，怎么协同？**
A：这正是赛题设计。协同只能通过 `broadcast()`/`send_to()` 交换信息（如自己发现的目标坐标、威胁警告），然后各自在本地维护一份"态势图"。参考 `competition/baselines/swarm_distributed.py`。

**Q2：怎么区分诱饵和真目标？**
A：诱饵静止、真目标移动。把连续多拍的 `detection.target_lat/lon` 记下来，位置不变的极可能是诱饵。`target_type` 字段靠不住（诱饵会伪装成 `"ground_vehicle"`）。

**Q3：怎么"摧毁"目标？没有开火命令？**
A：对同一真目标持续盯防（相机对准）累计 20 秒即判定摧毁，需满足协同阈值 K——**赛题二需 2 架同时盯防、赛题三需 3 架同时盯防**。策略重点是稳定跟踪 + 协同分配。被摧毁目标可从 `obs.briefing.score_view` 或上报反馈间接判断。

**Q4：我的 UAV 被击毁了怎么办？**
A：赛题三中，runner 检测到 `obs.self.status == "destroyed"` 后自动停止调用你的 `decide()`，你无需在代码里处理。但你的队友只能通过**通信心跳超时**察觉你失联——所以平时要记得广播心跳。

**Q5：`--seed` 是干什么用的？**
A：随机化场景（目标轨迹、威胁区、起始位置都从 seed 派生）。同 seed → 同场景，完全可复现。用它做泛化训练与回归测试。

**Q6：可视化界面显示的分数和我 Agent 拿到的一样吗？**
A：一样。两者来自同一个评分运行时，可视化只是把结果渲染成面板。

**Q7：报错了——"SCORING.md 说的维度对不上"？**
A：`旧版评分文档` 是**已废弃的旧版评分文档**。请以本手册 [§4](#四评分体系) 为准。
